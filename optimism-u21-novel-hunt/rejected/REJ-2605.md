# REJ-2605 — legacy games retain an old pause resolver after shared migration

**Hypothesis.** Games created before interop cache old ASR/DelayedWETH references, so pausing the shared lockbox fails to stop their claims or ETH release.

**Killed by current v9 source.** The migrator reinitializes each chain's existing DelayedWETH to the shared lockbox before migrating its Portal, then reinitializes the old ASR to the same shared lockbox. Old games keep the same object addresses but those objects' pause resolver changes in place. The loop and all upgrades are one transaction; if the old resolver is paused, `_migratePortal` reverts and rolls back the earlier WETH update.

**Exact evidence.** `src/L1/opcm/OPContractsManagerMigrator.sol:265-272,412-430,469-555`; `src/dispute/DelayedWETH.sol:47-64,98-108`; `src/dispute/AnchorStateRegistry.sol:94-108,135-143`.

No production migration had occurred at the research block, so an exact future OP+Unichain migration fork remains worthwhile, but no U21-deployed stale reference survives today.
