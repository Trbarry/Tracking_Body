# REJ-2604 — mutable L2 chain ID or resource config breaks super-root proofs/metering

**Hypothesis.** A caller changes `l2ChainId` after game/proof creation, or violates ResourceMetering invariants, redirecting a super-root proof or breaking deposits.

**Killed by.** Neither field has a public setter. Both are written by the versioned initializer; the current initializer is consumed. Standard v9 upgrades load the existing chain ID/resource config, and the extra-instruction allowlist does not permit either override. Interop migration preserves both. `setGasLimit` is owner-only and bounded by resource limit + system gas and 500m; resource initialization validates all metering invariants.

**Exact evidence.** `src/L1/SystemConfig.sol:150-160,203-265,398-409,494-526`; `src/L1/OptimismPortal2.sol:437-445,851-859`; `src/L1/opcm/OPContractsManagerV2.sol:244-275,347-375,627-652`; `src/L1/opcm/OPContractsManagerMigrator.sol:432-466`; `FeatureStateMachineTest.test_gasLimitBoundsAreEnforcedOnSystemConfigOwner`.

A proxy upgrade could change them, but the PA owner is already fully trusted and this is not a permissionless path.
