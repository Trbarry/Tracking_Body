REJ-1204 — "`deleteProvenWithdrawal` is permissionless and unpaused: delete (or repeatedly delete) a proof that could
still finalize, resetting the victim's 7-day clock"

Killing facts (v9:src/L1/OptimismPortal2.sol:711-728, fork tests in test/poc/lane12/Lane12.t.sol):
- Deletion requires `game.status() == CHALLENGER_WINS` or `anchorStateRegistry.isGameBlacklisted(game)`. `status` is
  written once at resolution; `disputeGameBlacklist[g]` is only ever set to true
  (v9:src/dispute/AnchorStateRegistry.sol:184) and there is no un-blacklist. `checkWithdrawal` (L702) needs
  `isGameClaimValid`, which is false for both. So a deletable proof is already unfinalizable.
- Valid finalized game -> `OptimismPortal_DisputeGameNotInvalidated` (test_R06_delete_validGame_reverts_NotInvalidated).
- In-progress game (latest DGF entry, status 0) -> same revert (test_R06_delete_inProgressGame_reverts_NotInvalidated).
- The game inspected is the one stored in the entry being deleted; a second submitter's proof against a valid game
  is untouched and finalizes (test_R06_delete_doesNotAffectOtherSubmitters).
- Deleting while paused or after finalization changes nothing that is read again
  (test_R06_delete_afterBlacklist_permissionless_evenWhenPaused; `finalizedWithdrawals` stays true).
Residual facts kept for other lanes: no pause gate; `proofSubmitters[h]` keeps the stale address; the blacklist read
uses the portal's current registry. Same conclusion as lane 05 REJ-0501 / REJ-0506.
