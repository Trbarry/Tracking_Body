REJ-0906 — "pause-identifier flip lets a paused chain slip through the migration / or leaves a consumer on the old identifier"
Idea: U21 made the lockbox the pause identifier; migrate() swaps the lockbox, so a paused chain could be unpaused, or
some contract could keep reading the retired lockbox's pause.
Killing facts:
- `_migratePortal` L498 checks `_systemConfig.paused()` (old lockbox identifier + global) BEFORE the portal is repointed;
  `migrateToSharedDisputeGame` L537 re-checks against the new identifier. Guardian-only inputs.
- After migration (fork reads): portal.ethLockbox, old ASR.ethLockbox, old DelayedWETH.ethLockbox (both chains),
  SystemConfig.paused() (-> portal.ethLockbox().paused()), hence L1CDM/L1StandardBridge/L1ERC721Bridge.paused(), all
  resolve to the shared lockbox. Nothing with funds still reads the retired lockbox's identifier; the retired lockbox's
  own `unlockETH` is unreachable anyway (REJ-0902, PRIM-0901).
- v8 `ETHLockbox.paused()` = systemConfig.paused() keyed on `portal.ethLockbox()`; v9 = isLocalOrGlobalPaused(address(this)):
  same identifier for all four chains today (portal.ethLockbox == the lockbox, checked).
- SystemConfig.setFeature(ETH_LOCKBOX) guard (L543-555) is moot on these chains (feature already true, cannot be disabled).
Side effect kept as PRIM-0904 (one identifier now pauses both chains' legacy games/bond withdrawals) — by design.
