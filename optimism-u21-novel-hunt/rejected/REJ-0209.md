REJ-0209 — Proxy special slots: L1ChugSplashProxy, ResolvedDelegateProxy, ProxyAdmin, OZ-v5 slot

Checked at N on all four chains:
- L1StandardBridge (L1ChugSplashProxy): EIP-1967 implementation `0xb37a11aa..`, admin = chain ProxyAdmin; `ProxyAdmin`
  slot 3 byte 20 (`upgrading`) = 0 so the proxy is not frozen; proxy type 1 (CHUGSPLASH).
- L1CrossDomainMessenger (ResolvedDelegateProxy): `implementationName[self]` (keccak(self . 0)) =
  "OVM_L1CrossDomainMessenger" (short-string encoding `..0034`), `addressManager[self]` (keccak(self . 1)) = the chain's
  AddressManager, whose entry now points at `0x7d4ec7fb..`; `proxyAdmin()` resolves through `AddressManager.owner()` to the
  chain ProxyAdmin; proxy type 2, implementation name set. Slots 0/1 of the messenger itself hold the `_initialized` byte
  at offset 20 and zero: the documented RDP collision does not affect this layout (suppressed per LANE_CONTEXT §6).
- ProxyAdmin: slot 0 owner = Safe, slot 3 = AddressManager | upgrading(false).
- ERC-7201 OZ-v5 Initializable slot `0xf0c57e16..6a00` = 0 everywhere (the OPCM guard at OPContractsManagerUtils.sol:359-382
  would have reverted otherwise).
- During the tx every proxy pointed at StorageSetter twice; nothing external is called in between (trace), and the final
  state has no proxy on StorageSetter.
Nothing attackable.
