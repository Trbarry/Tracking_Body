REJ-0808 — "Portal's new revert keys only on `_tx.sender == L2CDM`; a withdrawal with that sender but an arbitrary
target becomes permanently stuck or gives the attacker an `l2Sender == L2CDM` call into an arbitrary L1 contract"

Killing facts
1. The L2ToL1MessagePasser records `msg.sender`; the L2CDM calls it only from `_sendMessage` with
   `_to = otherMessenger` (L2CrossDomainMessenger.sol `_sendMessage`), and refuses to relay a message whose target is
   itself or the message passer (:59-61). Verified on the live predeploy: both revert with
   "cannot send message to blocked system address" (test_l2_cdm_cannot_be_made_to_withdraw_to_arbitrary_target),
   so neither `initiateWithdrawal` nor the passer's `receive()` can be reached with `msg.sender == L2CDM` and a
   chosen target.
2. Bedrock-migrated legacy withdrawals were all built as L2CDM -> L1CDM `relayMessage` (observed: 17 real ones).
3. All 37 L2CDM-sender proofs in the sampled window target the L1CDM.
Status: dead.
