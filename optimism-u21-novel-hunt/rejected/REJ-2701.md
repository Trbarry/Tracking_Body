# REJ-2701 — duplicate-chain super root directly authorizes an OP withdrawal

Status: Rejected as a candidate; retained as PRIM-2702.

Hypothesis: Because L1 accepts duplicate chain IDs and returns the first match, a permissionless creator can choose an invalid OP output root that the portal will accept.

Reproduction: On the real block-26430859 fork, `SuperRootPrimitivesTest.test_type9PermissionlessAndDuplicateChainIdsFirstWins` paid the live 0.08 ETH bond and created a real type-9 clone with two chain-10 entries. The clone returned the first root and was both factory-proper and respect-snapshotted.

Exact killing fact: The new game was `IN_PROGRESS` and `AnchorStateRegistry.isGameClaimValid(game) == false`. Portal proving rejects challenger-wins games and finalization separately requires the current ASR to report the game claim valid (`OptimismPortal2.sol:424-450,671-704`). Claim validity requires finalized `DEFENDER_WINS` (`AnchorStateRegistry.sol:328-352`). Starting from the live canonical anchor, the Kona transition constructs the next root through the sorting constructor (`rust/kona/crates/proof/proof-interop/src/pre_state.rs:70-100`; constructor at `rust/kona/crates/protocol/interop/src/root.rs:22-27`), so a malformed final claim is an ordinary challengeable invalid proposal.

Residual: A disagreement with another consumer, or a separate wrong-resolution bug, could revive the composition. No such disagreement was found in Solidity portal lookup or Go withdrawal tooling; both use first-match.
