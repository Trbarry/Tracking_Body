# REJ-2410 — Persistent failed bit permits a second execution after successful replay

## Idea

`failedMessages[hash]` remains true after a later successful replay. Since the replay branch only requires the failed bit, call it again for a second economic execution.

## Killing fact

Replay admission does require `failedMessages=true`, but immediately afterward the messenger requires `successfulMessages[hash]==false` (`CrossDomainMessenger.sol:239-254`). Successful relay sets that bit and the post-call assertion protects the same write against reentrancy (`:288-293`). The fork test observes both bits true after successful replay and a third call reverting “message has already been relayed” (`mirror/lane-24/tests/WithdrawalFinalization24.t.sol:359-399,430-453`).
