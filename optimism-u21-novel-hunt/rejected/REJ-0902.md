REJ-0902 — "make an authorized portal call its lockbox with attacker-chosen parameters via a withdrawal"
Idea: L2 withdrawal with target = lockbox and data = unlockETH(x) / lockETH() / migrateLiquidity(..) / authorizePortal(..);
or reach `ethLockbox.unlockETH` from another portal code path.
Killing facts (v9 @ ba6fcadb; deployed bytecode identical):
- OptimismPortal2 has exactly ONE arbitrary external call: L627 `SafeCall.callWithMinGas(_tx.target, …)`; it sits inside
  the window `l2Sender = _tx.sender` (L618) … `l2Sender = DEFAULT` (L630).
- `ethLockbox.unlockETH` is called from exactly one place, L614, with `_tx.value` of a withdrawal that already passed
  `checkWithdrawal` (L607) and was marked finalized (L610), BEFORE l2Sender is set — so the lockbox guard passes only there.
  `lockETH` call sites: L511 (owner-only migrateLiquidity), L663 (failed-withdrawal re-lock), L758 (deposit).
- Guard 1: `_isUnsafeTarget` (L846-849) = `target == address(this) || target == address(ethLockbox)`, enforced at prove
  (L402) AND at finalize (L599, before any state change). Fork: finalize with target = own lockbox ->
  `OptimismPortal_BadTarget` on OP today and on both portals after migration (target = shared lockbox).
- Guard 2: ETHLockbox.unlockETH L169 `sender.l2Sender() != DEFAULT -> ETHLockbox_NoWithdrawalTransactions`. Fork: prank
  portal with slot 50 (l2Sender) != 0xdEaD -> revert.
- authorizePortal / authorizeLockbox / migrateLiquidity: `_assertOnlyProxyAdminOwner` (msg.sender == ProxyAdmin.owner()),
  receiveLiquidity: `authorizedLockboxes[msg.sender]`; initialize: reinitializer(1) with `_initialized == 1` + admin check.
- v8 -> v9 did not change `_isUnsafeTarget` or the unlock call site (diff shows no change in those hunks).
- l2Sender == DEFAULT spoof: needs an L2 withdrawal whose sender is 0x…dEaD, i.e. an L1 contract at
  0xdEaD - 0x1111000000000000000000000000000000001111 or the key of 0xdEaD: infeasible.
