# REJ-2201 — legacy SystemConfig bytes collide with new dependencies

## Hypothesis

ETHLockbox, AnchorStateRegistry, or DelayedWETH might reinterpret a nonzero legacy `systemConfig` address as a new v9 dependency, or a new field might overwrite live packed state.

## Killing facts

- v9 replaces each old field with a same-size address spacer at the same slot/offset: ETHLockbox `src/L1/ETHLockbox.sol:66-78`, ASR `src/dispute/AnchorStateRegistry.sol:33-59`, WETH `src/dispute/DelayedWETH.sol:42-48` at pinned v9.
- Live legacy words were nonzero but bit-identical N-1→N on all four chains. OP examples: lockbox/ASR slot 0 `0x00000000000000000000229047fed2591dbec1ef1118d64f7af3db9eb2900001`; WETH slot 4 `0x000000000000000000000000229047fed2591dbec1ef1118d64f7af3db9eb290`.
- Each new location was zero at N-1 and correct at N: lockbox slot 3 = shared SuperchainConfig, WETH slot 5 = chain lockbox, ASR slot 6 high 20 bytes = chain lockbox. ASR's low 96 bits were unchanged, including Soneium type 5.
- `StorageBoundaryTest.test_expectedDependencySlotsOnly` passes against deployed N-1/N bytecode.

## Disposition

Rejected. No old byte is read under a new meaning and no live packed byte was overwritten.
