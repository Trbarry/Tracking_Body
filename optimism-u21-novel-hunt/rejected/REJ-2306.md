# REJ-2306 — CGT mode can drain or duplicate lockbox ETH

## Hypothesis

Because the v9 portal is always configured with a lockbox, toggling custom-gas-token
mode might leave a path that unlocks historical ETH without an ETH liability or
migrates surplus into the wrong accounting domain.

## Killing fact

CGT rejects every positive-value ETH liability path: deposit checks `msg.value`,
prove/finalize check withdrawal value, and `migrateLiquidity` rejects CGT
(`OptimismPortal2.sol:406-409,500-512,583-589,741-759`). OPCM rejects CGT chains
before shared migration (`OPContractsManagerMigrator.sol:483-486`). Donation and
forced ETH remain possible but create only surplus. Live OP has CGT=false.

## Evidence

`test_cgtModeRejectsETHLiabilityPathsButDonationStillAccepts` verifies all three
reverts and the surplus-only donation; feature state is locally mutated and is not
claimed as production state. Passive reads show false at N and later.

## Conclusion

Killed. Enabling CGT after accumulating ETH could freeze value until a privileged
configuration correction, but that requires privileged misuse and exposes no drain.
