REJ-0505 — "A proof created before the registry swap (migrateToSharedDisputeGame / OPCMv2.migrate) survives and is consumed after"
Killing facts:
- `OPContractsManagerMigrator.migrate` always deploys NEW ETHLockbox, DisputeGameFactory and AnchorStateRegistry proxies (`_loadOrDeployProxy(address(0), …)`) and calls `portal.migrateToSharedDisputeGame(newLockbox, newASR)` inside the same transaction; `migrateToSharedDisputeGame` reverts on the same registry (:548).
- Lock 1: `newASR.isGameRegistered(old)` looks the game's own (type, rootClaim, extraData) up in the NEW factory and compares addresses (ASR :227-237). Clone addresses are CREATE2 from the factory, so a twin created in the new factory has a different address.
- Lock 2: the new ASR's first `initialize` sets `retirementTimestamp = block.timestamp` (:130-132) → every older game is retired (:262), and games created in the migration block itself are retired too (`<=`).
- Fork simulation with the real deployed implementations (`MigrationSurvivalTest`): real matured proof → `InvalidRootClaim` after the swap; twins of the honest game and of an attacker game are created in the new factory at different addresses; even after the attacker's twin becomes `isGameClaimValid`, the pre-swap shadow proof still reverts `InvalidRootClaim`.
- Deletion after the swap consults the new registry's blacklist only (PRIM-0504) — no path to resurrect anything.
Not covered: the full `OPContractsManagerV2.migrate` transaction (simulated the same-lockbox variant of the portal call).
