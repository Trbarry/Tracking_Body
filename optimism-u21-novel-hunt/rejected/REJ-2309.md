# REJ-2309 — Interop liquidity migration is permissionless or observably non-atomic

## Hypothesis

An attacker might invoke public OPCM migration or separate the portal pointer change
from the old-lockbox sweep, leaving liabilities backed in an inaccessible contract.

## Killing fact

`OPContractsManagerV2.migrate` requires delegatecall and then delegatecalls the
migrator (`OPContractsManagerV2.sol:293-313`). In production that execution context
is the ProxyAdmin owner Safe; all outbound proxy-owner checks see the authorized
Safe. Direct calls fail the delegatecall guard. Within `_migratePortal`, new
authorization, feature/pointer changes, portal sweep, old lockbox sweep, and ASR
update occur in the same EVM transaction (`OPContractsManagerMigrator.sol:475-555`).
Any failure reverts the batch. Re-migration, CGT, pause, and duplicate IDs are
rejected earlier (`OPContractsManagerMigrator.sol:129-328`).

## Evidence

Fork guard test observes non-owner and inactive-interop reverts. Live reads show
INTEROP=false and no migration/custody events in U21.

## Conclusion

Killed as a permissionless current attack. A trusted owner could call lower-level
pieces incorrectly, but privileged misuse is not a bounty finding; the documented
planned OPCM path is atomic.
