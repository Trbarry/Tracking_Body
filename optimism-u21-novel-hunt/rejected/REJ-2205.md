# REJ-2205 — DGF dynamic mapping payload is semantically corrupted

## Hypothesis

Because `gameArgs` is dynamic bytes, U21 could silently shift packed fields, mismatch implementations and schemas, or accidentally configure Soneium as type 9.

## Killing facts

- DGF storage snapshots are byte-identical across v7/v8/v9; `gameImpls`, `initBonds`, and `gameArgs` remain mapping bases 101, 102, and 105 (`snapshots/storageLayout/DisputeGameFactory.json:37-70`).
- Types 0–10 were queried on all four factories at N-1 and N. Only types 5/9 are nonzero, except Soneium where only type 5 is nonzero and respected.
- Implementations and bonds did not change. OP type 5 changed only its proposer; type 9 on OP/Ink/Unichain changed only `absolutePrestate`. All values decode under `LibGameArgs` (`src/dispute/lib/LibGameArgs.sol:9-23,61-103,116-142`).
- The writes are owner-only and evented (`src/dispute/DisputeGameFactory.sol:298-327`). N values were unchanged at block 26433900. Exact payloads are in `mirror/lane-22/DGF_MAPPING_DIFF.md`.

## Disposition

Rejected. The observed deltas are coherent configuration updates, not storage reinterpretation.
