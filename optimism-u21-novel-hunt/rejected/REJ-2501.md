# REJ-2501 — delete a proof that can later finalize

## Idea

Permissionless deletion might remove an honest proof while its game is merely in progress, defender-wins, paused, retired, unregistered, or temporarily not proper, and that game might later become valid.

## Killing fact

The v9 gate is exactly `status == CHALLENGER_WINS || currentASR.blacklist[game]` (`OptimismPortal2.sol:711-725`). It does not use the broader, time-varying `isGameProper`/`isGameClaimValid` predicates. Every game implementation makes challenger-wins terminal: Fault `resolve` is one-shot (`FaultDisputeGame.sol:704-717`), SuperFault is one-shot (`SuperFaultDisputeGame.sol:673-686`), ZK is one-shot (`zk/ZKDisputeGame.sol:575-640`), Permissioned inherits Fault, and SuperPermissioned never becomes challenger-wins. The blacklist only ever changes false to true (`AnchorStateRegistry.sol:177-186`).

Fork tests cover in-progress and defender rejection, challenger/blacklist success, and deletion during a real pause. No deletable-now/valid-later state survived.

Disposition: Rejected; no candidate.
