# REJ-2105 — DGF prestate write retroactively changes existing games

Hypothesis: Updating factory `gameArgs[9]` makes an in-flight clone execute against the new prestate or point at a stale ASR/WETH.

Killing fact: DGF copies `gameArgs` into clone immutable args only at creation (`DisputeGameFactory.sol:174-215`). Pre-U21 respected games on OP (`0x675E...00d10`), Ink (`0x40be...942cc`), and Unichain (`0x3073...a68d8`) return the old `0x031ac6...e1df` prestate before and after U21; every later type-9 clone returns `0x03e5a5...37c9`. Their ASR and WETH proxy pointers remain the correct same-chain proxies. The old games stayed registered, respected, unretired, and proper across the boundary. Exact reads are in `dispute-state.json`.

Disposition: Rejected as retroactive reinterpretation. The deliberate old/new population split remains PRIM-2103 and deserves review only if the old prestate itself is shown unsound.
