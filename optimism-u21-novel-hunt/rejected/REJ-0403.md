REJ-0403 - "freeze a victim's messenger withdrawal by making its relay revert forever" (new v9 revert as DoS)

Idea: since v9 reverts the whole finalize when the L1CDM call fails, pre-set `failedMessages[h]` or
`successfulMessages[h]` for the victim's pending message so `assert(!failedMessages[h])`
(CrossDomainMessenger.sol:243) or the already-relayed `require` (:254) fails on every attempt -> funds frozen.

Killing facts:
- first write to either mapping for hash h requires `_isOtherMessenger()`; the replay branch requires
  `failedMessages[h]` already true (:247). `h` commits to (nonce, sender, target, value, minGasLimit, message)
  and the L2CDM nonce is unique, so only the victim's own withdrawal can carry that calldata from sender 0x42…07.
- a non-messenger withdrawal carrying the same relayMessage calldata runs the replay branch and reverts with
  "message cannot be replayed" (Fab.t.sol::test_cond_senderNotL2CDM_targetL1CDM_relayReverts) - it is consumed,
  the victim's message is untouched.
- the portal cannot be made to call the L1CDM twice in one finalization: nested finalize -> NoReentrancy (:594);
  prove / delete / deposit make no calls to arbitrary targets.
- the pause source is identical for portal and messenger (SystemConfig.sol:574-576, L1CrossDomainMessenger.sol:98),
  so "portal open, messenger paused" does not exist.
- gas: any finalizer can simply send more gas; thresholds are far below the 16,777,216 per-tx cap for all
  realistic messages (500 KB synthetic message relays at ~12.8M outer gas).
What remains is self-inflicted only: message to L1CDM / portal, already-relayed legacy v0 message, message of
many hundreds of KB whose relay cannot fit under the per-tx gas cap (documented / suppressed classes).
