REJ-0410 - portal as `msg.sender` against contracts that trust it (unsafe-target set too small)

Idea: `_isUnsafeTarget` only blocks the portal itself and the CURRENT lockbox (OptimismPortal2.sol:846-849).
A withdrawal could target (a) a lockbox that still authorises the portal, (b) the L1CDM pretending to be the
other messenger, (c) another chain's lockbox.

Killing facts:
- `ETHLockbox.unlockETH` reverts `ETHLockbox_NoWithdrawalTransactions` whenever the calling portal's `l2Sender`
  is not the default (ETHLockbox.sol:169-171) - i.e. always during a withdrawal call; `lockETH` only accepts ETH.
- `L1CDM._isOtherMessenger` additionally requires `portal.l2Sender() == 0x42…07` (L1CrossDomainMessenger.sol:137);
  with any other sender the call takes the replay branch (PRIM-0403 table).
- each sibling chain has its own lockbox / portal pair; a lockbox only serves `authorizedPortals`.
- nested calls back into the portal during the target call: finalize -> NoReentrancy; prove / delete / deposit
  / donateETH have no effect on the running finalization.
