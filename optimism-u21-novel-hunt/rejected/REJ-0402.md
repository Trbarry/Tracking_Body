REJ-0402 - "message failed-replayable in the messenger AND still finalizable again in the portal"

Idea: get `failedMessages[h] = true` (ETH credited to L1CDM) while `finalizedWithdrawals[wd]` stays false, then
finalize again -> second unlock from the lockbox (invariant B).

Killing facts:
- `finalizedWithdrawals[withdrawalHash] = true` is written before the call (OptimismPortal2.sol:610); the only
  ways it is undone are full-transaction reverts, which also undo `failedMessages` and the ETH transfer.
- `failedMessages` can first be set only through the other-messenger branch, i.e. only inside
  `portal -> L1CDM.relayMessage` with `portal.l2Sender() == L2CDM` (L1CrossDomainMessenger.sol:136-138 and
  CrossDomainMessenger.sol:239-248). No second caller exists.
- second finalize: `OptimismPortal_AlreadyFinalized` (checkWithdrawal :677), independent of submitter / game.
Fork evidence: Fab.t.sol::test_messenger_failed_then_replay_and_no_double; Fab2.t.sol forced-fail test (portal
finalized, message failed, later replay delivers once, third relay reverts);
CrossVersion.t.sol::test_failedV8_upgrade_replayV9 (same across the real upgrade).
