# REJ-2308 — Proof deletion during callback enables replay or unlock without proof

## Hypothesis

The new permissionless `deleteProvenWithdrawal` might be called reentrantly after
the finalized bit is set, then allow the same value to be proven/finalized again or
make a partially executed finalization escape validation.

## Killing fact

Deletion is allowed only when the stored game has permanently resolved
CHALLENGER_WINS or the ASR reports it blacklisted
(`OptimismPortal2.sol:707-728`). A proof that passed `checkWithdrawal` has a valid
claim at that point (`OptimismPortal2.sol:671-705`). Deleting a proof never clears
`finalizedWithdrawals`; the finalized bit is keyed only by withdrawal hash and is
set before the callback (`OptimismPortal2.sol:603-618`). A transaction that later
reverts restores deletion, finalization, and unlock together.

## Evidence

The real valid fixture's deletion attempt reverts
`OptimismPortal_DisputeGameNotInvalidated` in
`test_migrationAndProofDeletionGuards`.

## Conclusion

Killed. Proof deletion changes proof availability, not custody or replay protection.
