# REJ-2405 — Sender-only messenger protection is bypassable by target mismatch

## Idea

The v9 rollback condition checks only `_tx.sender == L2_CROSS_DOMAIN_MESSENGER`, not `_tx.target == L1CrossDomainMessenger`. Try (a) L2 messenger sender/non-messenger target and (b) non-messenger sender/L1 messenger target.

## Killing fact

Both synthetics behave exactly as the sender-only condition says: (a) a failed call rolls back; (b) a failed call finalizes false (`mirror/lane-24/tests/WithdrawalFinalization24.t.sol:337-357`). But production L2 messenger messages always call `_sendMessage` with `address(otherMessenger)` (`CrossDomainMessenger.sol:178-190`), and the L2 implementation initiates that withdrawal through the message passer (`L2CrossDomainMessenger.sol:92-106`). A non-messenger L2 sender cannot authenticate as `otherMessenger` in the L1 messenger (`L1CrossDomainMessenger.sol:135-142`).

The apparently over-broad synthetic condition therefore does not yield an alternate genuine message path. The source itself documents why checking sender is sufficient (`OptimismPortal2.sol:649-650`).
