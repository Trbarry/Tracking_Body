# REJ-2704 — cross-registry anchor injection into today's OP ASR

Status: Rejected for current state and the documented migration.

Hypothesis: Because `isGameRegistered` no longer checks `game.anchorStateRegistry() == address(this)` and anchors are shared across types, anyone can anchor a valid game from another ASR/security domain.

Exact killing fact today: Registration is still address-exact through the ASR's configured factory UUID mapping (`AnchorStateRegistry.sol:215-237`). OP factory type-5 and type-9 packed args both embed the OP ASR `0x23B2...D113`; a clone from Soneium/another factory does not equal the OP factory's UUID-mapped address. `setAnchorState` additionally requires full current-ASR claim validity and a newer sequence (`AnchorStateRegistry.sol:328-372`).

Exact killing fact at planned migration: The migrator deploys a fresh DGF and fresh ASR, initializes them together, then switches both portals atomically (`OPContractsManagerMigrator.sol:191-285,475-555`). Existing games in either old factory are not registered in the new ASR's factory.

Residual: Reusing a DGF while changing its game args to another ASR would make this primitive relevant, but that is not the v9 migration path.
