# REJ-2606 — closed-game `claimCredit` releases ETH while paused

**Hypothesis.** Legacy Fault/ZK `closeGame` returns before its pause check once bond mode is decided, allowing `claimCredit` to bypass the lockbox pause.

**Killed by.** A first claim on an already-closed legacy game can update `hasUnlockedCredit` and schedule a DelayedWETH unlock while paused, but no ETH moves. The value-bearing phase calls `DelayedWETH.withdraw`, whose first check is the same lockbox pause. SuperFault is stricter: it checks pause before even the closed-game return. On a real closed type-8 OP game, the fork advanced only zero-credit bookkeeping; a direct real DelayedWETH withdrawal reverted.

**Exact evidence.** `src/dispute/FaultDisputeGame.sol:979-1016,1021-1040`; `src/dispute/SuperFaultDisputeGame.sol:945-995`; `src/dispute/zk/ZKDisputeGame.sol:647-716`; `src/dispute/DelayedWETH.sol:98-108`; `PauseMatrixTest.test_valueMovingAndStatePathsUnderLockboxPause` using game `0xfb4D9A677aebBeAB9807c8bCc3D0FCd84ff9E826`.
