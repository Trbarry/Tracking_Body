# REJ-2202 — public initializer replay or unlocked implementation takeover

## Hypothesis

Unchanged init versions across v8→v9 might leave a gap, U21's reset might leave `_initialized` zero, or singleton implementations might be directly initializable.

## Killing facts

- All `ReinitializableBase` versions are unchanged across v7/v8/v9: Portal/SystemConfig/messenger/bridges=3, lockbox/ASR/DGF/WETH=1, SuperchainConfig=2. OZ rejects unless `_initialized < version` (`lib/openzeppelin-contracts-upgradeable/contracts/proxy/utils/Initializable.sol:95-114`).
- Same-version replay was deliberately privileged: OPCM masks one byte through StorageSetter and atomically reinitializes/restores the proxy (`src/L1/opcm/OPContractsManagerUtils.sol:352-386`). Target initializers call `_assertOnlyProxyAdminOrProxyAdminOwner`, defined at `src/universal/ProxyAdminOwnedBase.sol:102-105`.
- Every proxy's final initialized byte at N equals its intended version. Every one of 11 unprivileged initializer calls fails in `StorageBoundaryTest.test_publicReinitializersAreClosedToUnprivilegedCaller`.
- All 11 final singleton implementations are locked: ten direct slot-0 words end in `ff`; messenger has `ff` at offset 20. `StorageBoundaryTest.test_implementationInitializersAreDisabled` passes. OZ `_disableInitializers` writes `type(uint8).max` (`Initializable.sol:125-136`).

## Disposition

Rejected. There is no permissionless replay window or useful implementation initialization path.
