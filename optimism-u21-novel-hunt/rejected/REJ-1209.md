REJ-1209 — "the new 183,600-gas new-account reservation in SafeCall.callWithMinGas makes some value withdrawal
unfinalizable, or lets a finalizer deliver less than the requested gas"

Killing facts (v9:src/libraries/SafeCall.sol:121-172; fork test_R21_newAccountStateGas_reservation):
- The reservation only raises the `hasMinGas` threshold when `_value != 0 && _target.codehash == bytes32(0)`; the CALL
  itself still forwards `gas()`. A failed threshold reverts the whole finalize ("SafeCall: Not enough gas"), leaving
  the withdrawal unfinalized and retryable.
- Measured minimum portal gas, 1 ETH, gasLimit 0: 314,286 to an empty account, 127,782 to a funded EOA (delta 186,504);
  111,548 for zero value to an empty account. All far below the per-transaction gas cap, so nothing becomes
  unfinalizable.
- `codehash` is read from the address that is then called, in the same frame; an account with balance but no code
  has a nonzero codehash and is not charged the reservation (asserted in the test).
- Mainnet at 26433900 has no Amsterdam header fields: the state-gas charge the reservation anticipates is not live,
  so today this is only a higher gas requirement for the finalizer.
