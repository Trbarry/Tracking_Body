# REJ-2705 — permissionless CREATE2/pre-registration before the OP+Unichain migration

Status: Rejected.

Hypothesis: An attacker predicts the future shared DGF/ASR/lockbox addresses, deploys code or registers a game there now, then gains authority when governance switches the portals.

Exact killing facts:

- The migrator deliberately loads from `address(0)` and deploys fresh proxies (`OPContractsManagerMigrator.sol:191-222`).
- Salts mix the execution `block.timestamp` and contract name (`OPContractsManagerMigrator.sol:168-176`; `OPContractsManagerUtils.sol:236-302`).
- OPCM must be entered via delegatecall (`OPContractsManagerV2.sol:293-313,1073-1077`), and downstream ProxyAdmin/portal operations require the common ProxyAdmin owner. A permissionless delegatecaller has a different CREATE2 deployer and all privileged calls revert atomically.
- Prefunding a predicted empty address does not occupy it or prevent CREATE2 deployment.
- The new DGF is initialized and registered only inside the same migration transaction; old games/proofs remain in old factory domains.

Current-state check: OP chain ID 10 and Unichain chain ID 130 are distinct/ascending, have different ProxyAdmins with the same owner Safe, share SuperchainConfig and release 9.0.3, and have separate ASR/DGF/lockbox domains today. No permissionless pre-registration surface was found.
