REJ-0708 — pre-migration proofs/games "surviving" via deleteProvenWithdrawal, proofSubmitters or the legacy registry
Killing facts: after migrateToSharedDisputeGame the portal consults only the shared ASR (OptimismPortal2 L568, L702, L720).
  Legacy games are unregistered there, so every legacy proof fails checkWithdrawal (InvalidRootClaim) — the documented
  re-prove requirement. deleteProvenWithdrawal needs CHALLENGER_WINS or a blacklist entry in the CURRENT ASR (L718-723);
  a legacy proof against a DEFENDER_WINS legacy game is simply inert and is overwritten when its submitter re-proves
  (L483-484). The legacy ASR stays live (public setAnchorState still works there) but nothing in the portal, lockbox or
  shared factory reads it; legacy game bonds remain claimable (closeGame uses the game's own legacy ASR, which still
  reports the game proper).
Evidence: Lane07_Migration.t.sol::test_prepositioned_proof_dies_at_migration.
