# REJ-3005 — SafeCall/L1 gas-budget split permanently freezes L2→L1 messages

Hypothesis: L2 v2.2.1 computes old `baseGas`, while L1 v2.13.0 requires 135k reserve/15k buffer and SafeCall adds 183,600 for new value accounts, making messages unfinalizable.

Killing facts:

- Amsterdam/EIP-8037 is not active at N; the 183,600 check is conservative current-rule pre-positioning (`SafeCall.sol:119-135`).
- Portal forwards all remaining gas, not exactly `_tx.gasLimit` (`OptimismPortal2.sol:620-627`).
- A failed L2-messenger subcall causes Portal finalization to revert, retaining retryability with a higher transaction gas limit (`:639-653`).
- L1 public getters intentionally report remote L2 budgets (`L1CrossDomainMessenger.sol:61-74,116-125`); all live getters/baseGas values match pre-upgrade values.

Conclusion: rejected for permanent impact. At worst the demonstrated composition is extra gas/first-attempt failure; Amsterdam behavior is not locally reproducible.
