REJ-0604 — "l2ChainId / ResourceConfig / gasLimit can be moved to a value that breaks super-root proofs or bricks deposits"

Killing facts:
- `l2ChainId` is written only in SystemConfig.initialize (SystemConfig.sol:246), which is `reinitializer` + `_assertOnlyProxyAdminOrProxyAdminOwner`. OPCM upgrade re-passes the stored value and does not permit an `overrides.cfg.l2ChainId` instruction. On chain: 10 / 57073 / 1868 / 130, equal to the single chain id inside each chain's latest game extraData.
- There is no external `setResourceConfig` in v9 (call returns false on the fork); `_setResourceConfig` is reached only from initialize. On chain all four: (20_000_000, 10, 8, 1 gwei, 1_000_000, uint128.max) = Constants.DEFAULT_RESOURCE_CONFIG.
- `setGasLimit` (SystemConfig owner) is bounded to [maxResourceLimit + systemTxMaxGas = 21M, 500M] (:406-408); at the 21M floor deposits still meter normally (FeatureMachine.t.sol::test_owner_surface_bounds). Values: OP 40M, Ink 30M, Soneium 40M, Unichain 60M.
- ResourceMetering.sol is unchanged v8 -> v9.
Anything else reachable here is the chain operator (SystemConfig owner) choosing bad fee params: suppressed as operator misconfiguration.
