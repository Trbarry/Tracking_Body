REJ-0506 — "Deletion while paused / of an already-finalized withdrawal / front-running a finalize / reentrancy"
Killing facts:
- No `_assertNotPaused()` in `deleteProvenWithdrawal`: it succeeds while `SuperchainConfig.pause(lockbox)` is active (matrix branch B). Effect: one dead slot zeroed; prove/finalize stay blocked by pause. Pause alone (game temporarily improper) does NOT make a proof deletable (branch D).
- Finalized withdrawal: proof survives finalization; if the game is blacklisted afterwards the proof is deletable, `finalizedWithdrawals[h]` stays true, re-finalize reverts `AlreadyFinalized` (`test_v8_proof_finalizes_under_v9`). Only consequence: a `WithdrawalProofDeleted` event for a finalized withdrawal.
- Front-run: a state in which finalize succeeds is a state in which delete reverts (REJ-0501); ordering within a block cannot change that.
- Reentrancy: delete has no `l2Sender` guard, but during a finalize callback `finalizedWithdrawals[h]` is already set (:610) and delete only works on dead games; its two external calls are STATICCALL-style views on factory clones / the ASR.
- Delete → re-prove: the timer restarts, but the deleted proof could never have finalized, so no honest maturity is lost; an attacker cannot delete a proof that would have finalized.
