REJ-0104: Wrong-chain configuration or a stale/cross-chain pointer after a four-chain bundle

Idea: four chains upgraded by one multicall with hand-built inputs; a copy-paste could wire chain A's proxy to chain B's SystemConfig/portal/lockbox/ASR/DGF/WETH, or leave a pointer at a pre-U21 contract.

Killing facts:
- The upgrade input per chain contains only the SystemConfig address, game configs and two instructions; every sibling address is read on chain from that SystemConfig / its portal (`OPContractsManagerV2.sol:384-546`) and every config value is read back from the chain (`552-682`).
- Decoded initializer arguments of all 41 calls reference only same-chain proxies, the shared SuperchainConfig `0x95703e09...`, the Safe, or the OPCM (`U21_INITIALIZER_CALLS.md` section 3).
- Post-state wiring: 68 address-typed getters x 4 chains, 0 pointers into another chain's contract set, 0 unlabelled addresses (`lanes/LANE-01-report.md` section 4). `gameArgs(5)`/`gameArgs(9)` embed the chain's own ASR and DelayedWETH.
- `ETHLockbox.authorizedPortals(otherChainPortal)` and `authorizedLockboxes(anyLockbox)` are false for all 4x4 combinations.
- On-chain StandardValidator v4.1.1 returns no error for OP, Ink, Unichain; Soneium only `SCKDG-SHAPE,SCKDG-10` (no permissionless super game registered, unchanged by U21).
