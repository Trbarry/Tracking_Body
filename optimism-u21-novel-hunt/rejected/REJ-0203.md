REJ-0203 — Initializer version gap lets `initialize` be called again (proxy or implementation)

Idea: (a) `_initialized` < `initVersion()` on some proxy after the StorageSetter reset; (b) an initializer without caller
ACL; (c) an implementation left uninitialised, with delegatecall / ETH-moving paths.

Killing facts:
- `_initialized` at N == `initVersion()` on every proxy of the four chains: Portal 3, SystemConfig 3, L1CDM 3 (slot 0
  byte 20), L1StandardBridge 3, L1ERC721Bridge 3, SuperchainConfig 2, ETHLockbox/ASR/DelayedWETH/DGF 1,
  OptimismMintableERC20Factory 1 (POST_UPGRADE_STATE.json `initializedVersion`).
- Every initializer has `_assertOnlyProxyAdminOrProxyAdminOwner()` including the factory
  (src/universal/OptimismMintableERC20Factory.sol:65-67), and the zero -> initialize sequence is atomic inside
  `OPContractsManagerUtils.upgrade` (:352-386).
- `test_reinitializeRevertsForEveryCaller`: 10 initializers x 4 chains x 3 callers (random, Safe, ProxyAdmin) all revert
  "Initializable: contract is already initialized".
- Implementations: slot 0 = 0xff for all 11 (L1CDM impl: 0xff at byte 20). `proxyAdmin()` reverts on a bare implementation
  (no EIP-1967 admin slot, no RDP marker; ProxyAdminOwnedBase.sol:44-76) so even owner-gated functions are unreachable.
  None of the v9 L1 proxied contracts (nor their bases) contains `delegatecall` or `selfdestruct` (the only
  `selfdestruct` in the tree is the `Burner` helper of `Burn.eth`, src/libraries/Burn.sol:32; L1 only uses `Burn.gas`
  in ResourceMetering). `test_implementationsAreLocked` PASS
  (incl. `lockETH`/`receiveLiquidity`/`unlockETH` on the bare ETHLockbox implementation reverting).
- StorageSetter implementation `0x2476c911..` is callable by anyone but only writes its own storage; no proxy points at
  it after the tx (all EIP-1967 slots / AddressManager entries hold the final implementations).
- OZ-v5 ERC-7201 Initializable slot is 0 on all proxies; `ProxyAdmin.upgrading` is false (ChugSplash proxy not frozen).
Not covered here (dispute lane): the game implementations `0x19AF533C..` / `0x5C3eb47c..` are CWIA templates and are
not `Initializable`-locked (`createdAt() == 0` on both at 26433900); unchanged by U21 and not factory-registered games.
