REJ-0407 - "portal pays a value withdrawal from its own (zero) balance -> CALL fails -> finalized undelivered"

Idea: `_isUsingLockbox()` reads the CURRENT feature flag (OptimismPortal2.sol:806-808). If ETH_LOCKBOX were off at
finalize time the portal would skip `unlockETH`, the CALL with value would fail for lack of balance, a
non-messenger withdrawal would be marked finalized and nothing would be re-locked.

Killing facts: `SystemConfig.setFeature` reverts when disabling ETH_LOCKBOX (SystemConfig.sol:544-547);
`initialize` requires the flag on and a non-zero lockbox (OptimismPortal2.sol:839-843); live state: flag true and
portal balance 0 / lockbox funded on OP, Ink, Soneium, Unichain both before and after U21 (cast reads at 26430858
and 26433900). With the lockbox on, `unlockETH` either funds the portal with exactly `_tx.value` or reverts.
