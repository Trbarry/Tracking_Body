# REJ-2603 — malformed/repeated INTEROP migration reachable by an attacker

**Hypothesis.** INTEROP has no prerequisite validation in generic `setFeature`, allowing a chain to enter a shared-contract state without the required lockbox/ASR/DGF or to be migrated twice.

**Killed by.** The weak generic setter is PA/PA-owner-only. The intended migrator validates common PA owner and SuperchainConfig, rejects an already-true INTEROP flag, rejects zero/duplicate/out-of-order L2 IDs and CGT, checks the current pause, and performs all rewiring atomically. Once set, INTEROP cannot be unset, so a direct premature write can brick the intended migration—but only by the fully trusted upgrade role.

**Exact evidence.** `src/L1/SystemConfig.sol:528-560`; `src/L1/opcm/OPContractsManagerMigrator.sol:287-327,483-543`; `FeatureStateMachineTest.test_ethLockboxAndInteropAreOneWay`. All four live flags were INTEROP=false at N.
