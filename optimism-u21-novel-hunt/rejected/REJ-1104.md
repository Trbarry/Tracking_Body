# REJ-1104 — "U21 changed the pause identifier, so a guardian pause / an entry point is inconsistent"

Idea: v9 routes `paused()` of portal, SystemConfig, ASR, L1CDM through `ETHLockbox.paused()` =
`SuperchainConfig.isLocalOrGlobalPaused(lockbox)` (ETHLockbox.sol:112-114, SystemConfig.sol:574-576,
OptimismPortal2.sol:306-308). If any upgraded chain used the portal address as identifier before,
existing runbooks would pause nothing; or some value-moving entry point might ignore the pause.

Killing facts:
- All four chains upgraded by the U21 tx already had `isFeatureEnabled("ETH_LOCKBOX") = true` and a
  non-zero `ethLockbox()` at `l1pre` (cast on OP Mainnet, Ink, Soneium, Unichain SystemConfig /
  portal, both pins) → identifier = lockbox before and after; portal ETH balance 0 on all four.
- `test/poc/Differential.t.sol::test_D5_pause_consistency` (guardian prank = production incident
  path), 60 keys, **0 differences** between `l1pre` and `l1`
  (`evidence/lane11/diff-{l1pre,l1}-D5-pause.txt`):
  - `pause(lockbox)` and `pause(address(0))`: portal/lockbox/L1CDM/ASR `paused()` all true;
    `finalize…` and `proveWithdrawalTransaction` revert `0xb9c3c2ef OptimismPortal_CallPaused`;
    direct `L1CDM.relayMessage` reverts "CrossDomainMessenger: paused"; `lockbox.unlockETH` reverts
    `0x9e729942 ETHLockbox_Paused`; deposits (`depositTransaction`, `L1CDM.sendMessage`,
    `L1StandardBridge.depositETH`) still succeed — by design ("Unlocks are blocked when paused,
    locks are not", ETHLockbox.sol:158).
  - `pause(portal)`, `pause(systemConfig)`, `pause(l1cdm)`: accepted by SuperchainConfig but pause
    nothing, on BOTH forks (not a U21 regression; operator-runbook matter, notice line 86).
- Invariant campaign: 20+ guardian pauses interleaved with random actions; counter
  `vPausedSuccess` (prove / finalize / replay succeeding while paused) stayed 0.
