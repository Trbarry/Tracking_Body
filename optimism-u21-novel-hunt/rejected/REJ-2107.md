# REJ-2107 — StandardValidator/mutation mismatch is exploitable

Hypothesis: OPCMv2 mutates fields the release validator does not cover, leaving a malicious or broken configuration accepted.

Killing fact: With the exact decoded proposer and prestate inputs, deployed StandardValidator `0x9E1D...41B2` returns an empty error string for OP Mainnet, Ink, and Unichain. Soneium returns `SCKDG-SHAPE,SCKDG-10` because its executed calldata explicitly disables type 9 and selects respected type 5; OPCMv2 requires the selected respected type to be enabled but permits a permissioned-only upgrade configuration (`OPContractsManagerV2.sol:684-796`). The StandardValidator's standard super-game branch expects both type 5 and type 9 (`OPContractsManagerStandardValidator.sol:960-988`; `StandardValidatorUtils.sol:163-183`).

No hidden pointer or authority discrepancy accompanies Soneium's non-standard game shape: its full wiring and initializer state are correct, games are being created as type 5, and the permissionless type is deliberately zero.

Disposition: Rejected as a vulnerability. It is an operational validation exception that should be documented for permissioned-only chains, not a permissionless exploit.
