# REJ-2408 — Return bomb or reentrancy corrupts the finalization state

## Idea

Use enormous returndata or target reentrancy to exhaust Portal gas after the target executes, leaving inconsistent delivery/finalized state or enabling a second withdrawal.

## Killing fact

`SafeCall.callWithMinGas` performs CALL with output pointer/length zero and copies no returndata (`SafeCall.sol:156-171`), so a 64 KiB return bomb did not affect Portal finalization (`mirror/lane-24/tests/WithdrawalFinalization24.t.sol:264-273`). During execution `l2Sender` is set away from the default; nested finalization fails the explicit reentrancy guard (`OptimismPortal2.sol:591-595,617-630`). Any enclosing revert also rolls back the pre-call finalized bit atomically.
