REJ-1003 — "Sameness checks (`A.proxyAdminOwner() == B.proxyAdminOwner()`) are an authorization bypass with an attacker-deployed B"; "legacy proxies answer admin queries differently"

Killing facts:
- The only sameness check in v9 `src/` is `ProxyAdminOwnedBase._assertSharedProxyAdminOwner` (`ProxyAdminOwnedBase.sol:79-83`),
  used at `ETHLockbox.sol:189` (authorizeLockbox), `:208` (migrateLiquidity) and `:222` (`_authorizePortal`).
  The first two run after `_assertOnlyProxyAdminOwner()` (`:186`, `:205`); `_authorizePortal` is reached only from
  `authorizePortal` (`:126` owner check) and `initialize` (`:102` ProxyAdmin-or-owner check). An attacker contract
  that echoes the right owner still needs the ProxyAdmin owner to make the call.
- `OPContractsManagerMigrator.sol:296` compares `proxyAdmin().owner()` of the input SystemConfigs — input of an
  owner-only delegatecall.
- On chain (block 26433900) `proxyAdmin()` = `0x543bA4AA…` and `proxyAdminOwner()` = `0x5a0Aae59…` for the
  L1CrossDomainMessenger (ResolvedDelegateProxy path via `AddressManager(0xdE1FCfB0…).owner()`), the
  L1StandardBridge (L1ChugSplashProxy: owner is stored in the same EIP-1967 admin slot), portal, lockbox,
  DelayedWETH, ASR, DisputeGameFactory and SuperchainConfig. `ProxyAdmin.isUpgrading()` = false.
- An implementation called directly has an empty admin slot and fails the "OVM_L1CrossDomainMessenger" name
  probe (`ProxyAdminOwnedBase.sol:59-66`), so it reverts instead of resolving an owner.

Left for the OPCM lane: `OPContractsManagerUtils._adminFor` (`:397-403`) routes `upgrade` calls to the ProxyAdmin
that the target proxy self-reports; targets come from SystemConfig getters of an owner-supplied chain.
