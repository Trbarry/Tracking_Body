# REJ-2409 — A v8 pre-record messenger revert remains economically stranded after U21

## Idea

v8 finalized all failed Portal target calls. If the L1 messenger reverted before setting `failedMessages`, the Portal could have `finalized=true` while both messenger bits were false. U21's new rollback cannot repair an already-set historical bit.

## Historical falsification

The complete observed deployment window was scanned from block 25,900,000 (Portal still v5.6.1; v5.8.0 begins at 26,048,619) through N-1 block 26,430,858. Among 2,508 `WithdrawalFinalized` logs there was exactly one `success=false`:

- block 26,139,841, tx `0xcaaa4a154a865d2ab0264135001b1577b0cce0688de176fa1299e8f0b3992000`;
- withdrawal `0xad0a2811460d8a7f4ef1c467171ee312fb9b85f9ca8965fa44a7e9542cc68ec4`;
- genuine L2 messenger → L1 messenger outer call, but version-0 message nonce 114402;
- v1 hash `0x69fa…921a`: `successful=false, failed=false`;
- legacy v0 hash `0xaef8…b574f`: `successful=true` at N-1, N, and post-U21.

The messenger reverted because the migrated legacy economic message had already been relayed; it was not undelivered. This matches the v9 source's explicit legacy-already-relayed case (`OptimismPortal2.sol:643-647`). No evidenced value-bearing unrecorded failure survived the scan. See `REAL_WITHDRAWAL_EVIDENCE.md` for calldata and reads.

Rejected for lack of a production instance or current attack path; the hypothetical v8 state remains logically possible but U21 prevents new instances.
