REJ-1005 — "Old code now runs around a lockbox external call" (ResourceMetering + lockETH ordering, lockbox as withdrawal/message target, forged msg.sender == portal)

Killing facts:
- OP Mainnet, Ink, Soneium and Unichain already had `ETH_LOCKBOX` enabled and the same lockbox address at N-1
  (`portal.ethLockbox()` identical on `l1pre` and `l1`), so U21 did not introduce the `lockETH`/`unlockETH` calls
  into the deposit/withdraw paths of these chains; portal balance is 0 before and after.
- `depositTransaction` (`OptimismPortal2.sol:748-759`): `metered` runs its body first and meters afterwards
  (`ResourceMetering.sol`, unchanged since v7); the only new callee is the lockbox, which makes no outbound call
  in `lockETH` (`ETHLockbox.sol` lockETH: auth check + event).
- `unlockETH` refuses while the calling portal's `l2Sender` is set and is only callable by an authorized portal;
  the portal blocks `target == portal || target == ethLockbox` and re-entry into finalize (`l2Sender` guard).
  A withdrawal that calls `lockbox.lockETH` as the portal only returns ETH to the lockbox.
- The L1CDM blocks `target == portal` (no forged deposits from the messenger alias); a message targeting the
  lockbox reaches it with `msg.sender == L1CDM`, which is not an authorized portal.
- `Proxy`/`L1ChugSplashProxy` `address(0)` admin shortcut needs `msg.sender == address(0)`; StorageSetter
  (`0x2476c911…`) is not the final implementation of any of the 33 proxies touched by the upgrade tx.
- Storage layouts v8 vs v9 (`snapshots/storageLayout`): identical for OptimismPortal2, SystemConfig, L1CDM,
  SuperchainConfig, L1StandardBridge, L1ERC721Bridge, DisputeGameFactory, OptimismMintableERC20Factory; only
  `systemConfig -> spacer` + appended `ethLockbox` (ASR, DelayedWETH) and appended `superchainConfig` (ETHLockbox).
  Low slots of portal, L1CDM, L1StandardBridge, SystemConfig, SuperchainConfig are unchanged N-1 -> 26433900
  (except L1CDM `msgNonce`).
