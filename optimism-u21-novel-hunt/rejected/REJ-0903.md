REJ-0903 — "cross-portal authority once lockboxes are shared (or across sibling chains today)"
Idea: with msg.sender == portal A (withdrawal on chain A, arbitrary target/calldata), hit something on chain B that
trusts "a portal".
Enumeration of every `msg.sender`-is-portal style check in v9 src/ (grep over src/L1, src/universal, src/dispute, src/safe):
- ETHLockbox L136/L147/L163 — mapping lookups keyed by exact address (REJ-0901/0902).
- L1CrossDomainMessenger L137 `msg.sender == address(portal) && portal.l2Sender() == otherMessenger` — `portal` is that
  chain's own stored portal; portal A != portal B.
- StandardBridge L113 / ERC721Bridge L66 — `msg.sender == messenger` (own messenger).
- AnchorStateRegistry L376 — `msg.sender == ethLockbox.guardian()`.
- SystemConfig / SuperchainConfig / DGF / DelayedWETH / ProxyAdmin: owner, guardian or ProxyAdmin(-owner) only; no
  portal is owner/guardian of anything (reads: DGF owners = Safe, SuperchainConfig guardian = 0x09f7150D…).
Post-migration fork tests (Lane09PostMigration.t.sol, real migrated state, proof validity mocked only to inject):
- OP withdrawal -> UNI portal.depositTransaction{value}: shared lockbox balance unchanged (unlock by OP portal, re-lock
  by UNI portal); portals keep 0 balance. Conserving, no authority.
- OP withdrawal -> UNI portal.migrateLiquidity / migrateToSharedDisputeGame / initialize, -> UNI retired lockbox.lockETH:
  all sub-calls revert, WithdrawalFinalized(success=false), value re-locked into the shared lockbox.
- UNI portal on OP's retired lockbox: ETHLockbox_Unauthorized.
- A withdrawal on one portal can re-enter the OTHER portal's finalize (l2Sender guards are per-portal); that is an
  ordinary finalization of an independently proven withdrawal and gives nothing.
Pooled liability (UNI portal unlocking 100k ETH from a pool it contributed 18.27k to) works —
test_post_pooledLiability_byDesign — and is the documented interop trust model, not a finding.
