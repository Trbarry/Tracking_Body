REJ-0108: Ordering hazard - ETHLockbox v2.0.0 needs `SuperchainConfig.isLocalOrGlobalPaused`, which only exists from v2.5.0

Idea: if a chain's lockbox were upgraded while its SuperchainConfig is still 2.4.3, `ETHLockbox.paused()` would revert and with it `unlockETH`, `OptimismPortal2.paused()`, `AnchorStateRegistry.paused()` and `DelayedWETH.withdraw` (withdrawals and bond claims frozen).

Killing facts: call 0 of the bundle upgrades SuperchainConfig `0x95703e09...` to 2.5.0 before any chain; `OPContractsManagerV2._apply` line 818 reverts `OPContractsManagerV2_SuperchainConfigNeedsUpgrade` when `superchainConfig.version() < impl version`; the lockbox is initialised with `systemConfig.superchainConfig()` of the same chain; all four lockboxes report `superchainConfig() == 0x95703e09...` and `paused() == false` at N. The migrator has the same guard (`OPContractsManagerMigrator.sol`, `SuperchainConfigNeedsUpgrade`).
