# REJ-2702 — caller-selectable legacy/super proof type confusion

Status: Rejected.

Hypothesis: On a non-interop chain that respects type 9, a caller can present a legacy root for a super game (or a super-root preimage for a legacy game), bypassing chain-ID selection.

Exact killing fact: `OptimismPortal2.proveWithdrawalTransaction` selects the variant exclusively from the registered game's own `gameType()`: super types call `rootClaimByChainId(systemConfig.l2ChainId())`, all others call `rootClaim()` (`packages/contracts-bedrock/src/L1/OptimismPortal2.sol:411-450`). There is no caller-supplied variant bit and no branch on the INTEROP feature. `GameTypes.isSuperGame` includes types 5 and 9 (`dispute/lib/Types.sol:112-117`).

Production check: OP Mainnet has INTEROP=false, respects type 9, and all last 30 games still traverse the super branch. Thus the non-interop condition does not reopen legacy selection.
