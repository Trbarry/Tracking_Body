# REJ-2304 — Pause asymmetry duplicates or strands backing

## Hypothesis

Deposits remain allowed while proof/finalization and lockbox unlock are paused, so
pause might create liabilities without backing or let value be counted twice.

## Killing fact

The unpaused check is absent from deposit, but every positive-value deposit first
calls `lockETH{value: msg.value}` and emits that same `msg.value` as L2 mint data
(`OptimismPortal2.sol:741-795`). Locking is deliberately allowed while paused;
unlock is blocked (`ETHLockbox.sol:153-170`). Thus both backing and obligations
increase together, while old exits remain backed and delayed.

## Evidence

`test_pauseBlocksFinalizationButNotAdditionalLocking` observes a 1 ETH lockbox
increase and then `OptimismPortal_CallPaused` for the real mature withdrawal.
Pause is mocked only to reach the branch; the arithmetic uses deployed code.

## Conclusion

Killed as a conservation bug. A pause can delay exits, but it neither duplicates nor
strands backing independently of the intended pause authority.
