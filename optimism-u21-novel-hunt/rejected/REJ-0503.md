REJ-0503 — "Griefing-to-theft via proof-submitter identity (attacker proof selected instead of, or blocking, the victim's)"
Killing facts:
- `finalizeWithdrawalTransaction` uses `msg.sender`'s slot; `…ExternalProof` uses the explicitly named submitter (:496-498, :577-607). No fallback, no "latest proof", no iteration.
- An attacker proof against his own invalid type-9 game (bond 0.08 ETH, `initBonds(9)`) is only usable if that game is DEFENDER_WINS + finalized — the ordinary fault-proof safety assumption, not a lifecycle bug. With an honest challenger it resolves CHALLENGER_WINS: `checkWithdrawal(h, attacker)` → `InvalidRootClaim`, then deletable by anyone.
- An attacker proof against the SAME valid game (permissionless) only adds a second, later-maturing path; the victim's path matures first (`test_reprove_overwrites_and_duplicates`: victim passes `checkWithdrawal`, attacker `ProofNotOldEnough`).
- Respected-ness is `wasRespectedGameTypeWhenCreated` at both prove (:420) and finalize (ASR :338) — one frozen flag, no prove-time/finalize-time gap. Changing the respected type after the proof neither invalidates it nor makes it deletable (matrix branch E).
- Timing: proof must be newer than `createdAt` at prove (:433) and finalize (:692); minimum time creation→valid game is 3.5 d clock + 3.5 d airgap = proof maturity 7 d.
