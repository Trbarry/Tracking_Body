REJ-0501 — "Permissionless deletion of a proof that would (or could later) have finalized"
Idea: find a game state that satisfies the delete predicate now but is, or can become, `isGameClaimValid`; or a non-permanent CHALLENGER_WINS / blacklist.
Killing facts:
- Predicate (OptimismPortal2.sol:718-723): `status() == CHALLENGER_WINS || anchorStateRegistry.isGameBlacklisted(game)`. `isGameClaimValid` requires `!isGameBlacklisted` (AnchorStateRegistry.sol:293) and `status() == DEFENDER_WINS` (:348). The two sets are disjoint at every instant.
- `status` is written once: `resolve()` reverts unless IN_PROGRESS (SuperFaultDisputeGame.sol:675, FaultDisputeGame.sol:706, ZKDisputeGame.sol:577). There is no sub-claim status exposed through `status()`.
- Deployed ASR impl 0x2b27299c… has exactly five mutators (`cast selectors`): 0x17cf21a9 setAnchorState, 0x47a222c5 initialize, 0x7d6be8dc blacklistDisputeGame, 0x7fc48504 setRespectedGameType, 0xd5a3e12e updateRetirementTimestamp. No un-blacklist; `retirementTimestamp` only moves to `block.timestamp` (or is set once when zero, :130).
- Fork: delete reverts `DisputeGameNotInvalidated` on IN_PROGRESS, DEFENDER_WINS, retired, paused-only, respected-type-changed games, and at the exact timestamp at which `checkWithdrawal` passes (`CrossVersionTest.test_v8_proof_finalizes_under_v9`); 44 real proofs: 0 deletable (`SurveyTest`).
- ZK game (type 10, not registered on any of the four chains): a child of a CHALLENGER_WINS parent resolves CHALLENGER_WINS even with a valid ZK proof (ZKDisputeGame.sol:587-593) — still never finalizable, so deletion changes nothing.
Residual: only a registry swap or ASR implementation change (ProxyAdminOwner) alters the relation; see REJ-0505.
