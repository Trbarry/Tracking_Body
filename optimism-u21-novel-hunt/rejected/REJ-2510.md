# REJ-2510 — unset game types or Soneium type 5 make old proofs deletable

## Idea

OP Mainnet type-0/1 implementations are unset, and Soneium respects bondless type 5; cross-version game configuration might invalidate or expose proofs.

## Killing fact

OP reads at N-1, N, and later are identical: respected type 9, type 9 bond 0.08 ETH, type 5 implementation present/bond zero, type 0/1 implementations zero. Clearing a factory implementation pointer affects only future `create`; existing clone code and `_disputeGames` registration remain. Respect is captured into each game at creation and ASR reads that immutable bit (`AnchorStateRegistry.sol:239-247`), not the current factory implementation pointer.

Soneium indeed respects type 5 with zero bond, but `SuperPermissionedDisputeGame.initialize` requires `tx.origin == proposer` and immediately sets immutable terminal `DEFENDER_WINS` behavior (`SuperPermissionedDisputeGame.sol:51-78`). A permissionless attacker cannot create the game despite the zero bond; valid proofs are deletable only after Guardian blacklist.

Disposition: Rejected; no cross-chain permissionless deletion or proof invalidation.
