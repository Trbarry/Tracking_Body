REJ-0905 — "prove before migration, finalize after" / old-game acceptance by the shared AnchorStateRegistry
Idea: AnchorStateRegistry.isGameRegistered dropped the `game.anchorStateRegistry() == this` check (comment L217-224
names exactly the "net-new ASR proxy" case), so a pre-migration game (or one created in a legacy DGF after migration)
might satisfy the new shared ASR.
Killing facts:
- migrate() deploys a net-new DGF together with the net-new ASR; `isGameRegistered` asks the NEW DGF
  `games(gameType, rootClaim, extraData)` and compares the returned proxy address with the game: a legacy game is never
  equal to a proxy created by the new factory (even if an attacker re-creates the same UUID there).
- new ASR `retirementTimestamp == block.timestamp` of migration (first-init branch L128-130) -> every older game retired.
- legacy DGF implementations for types {0,1,8,4,5,9,10} are cleared in the same tx (fork: old OP DGF gameImpls(9)=0,
  gameImpls(5)=0), and no other type was registered on the OP / Unichain DGFs (only 5 and 9 set today).
- Fork test Lane09OldProofs.t.sol::test_oldGameProof_dies_at_migration: a proof record against OP Mainnet's REAL current
  anchor game 0x55A5CFd4… passes `checkWithdrawal` before migrate() and reverts `OptimismPortal_InvalidRootClaim` after;
  sharedASR.isGameRegistered = false, isGameRetired = true.
- Withdrawal hashes initiated on L2 before migration with target = future shared lockbox: `_isUnsafeTarget` is
  re-evaluated against the current `ethLockbox` at (re-)prove and at finalize -> BadTarget.
Documented-by-design remainder: users must re-prove.
