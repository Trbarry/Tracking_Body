PRIM-ID: PRIM-0302 — What a callee can still do while a withdrawal is executing

Source contracts: `src/L1/OptimismPortal2.sol`, `src/L1/ETHLockbox.sol`, `src/universal/CrossDomainMessenger.sol`.

Exact functions: `depositTransaction` (`OptimismPortal2.sol:741`), `donateETH` (`:381`), `proveWithdrawalTransaction` (`:390`), `deleteProvenWithdrawal` (`:711`), versus `finalizeWithdrawalTransactionExternalProof` (`:594-596`), `ETHLockbox.unlockETH` (`ETHLockbox.sol:163`, `:169`).

Trigger: the target of a withdrawal (or the final recipient behind L1CDM / L1StandardBridge) runs code during `SafeCall.callWithMinGas` (`OptimismPortal2.sol:627`).

Attacker-controlled inputs: the target's code; the value it received.

Required state: `l2Sender != DEFAULT_L2_SENDER` (inside a finalization).

State mutation:

| Re-entrant call | Outcome on the real contracts |
|---|---|
| `portal.finalize…` of another ready withdrawal | reverts `OptimismPortal_NoReentrancy` |
| `lockbox.unlockETH`, `lockETH`, `portal.migrateLiquidity` | revert (`ETHLockbox_Unauthorized`, not PAO) |
| `portal.depositTransaction{value: x}` | succeeds: lockbox +x, new L2 mint of x |
| `portal.donateETH{value: y}` | succeeds: portal balance +y, lockbox unchanged |
| `L1CDM.relayMessage` replay of the message being relayed | reverts (not failed yet) |
| `prove…`, `deleteProvenWithdrawal` | no `l2Sender` check; no value effect |

External calls: as listed.

Cross-contract dependency: `ETHLockbox.unlockETH` re-reads `portal.l2Sender()`; `L1CDM` uses its own `xDomainMsgSender` guard.

Broken or weakened assumption: none. Net lockbox change over the tx is always `−value + (re-deposited)`.

Candidate compositions: together with PRIM-0303 (stranding in the portal) and PRIM-0304 (reverse nesting from an L1CDM replay).

Evidence: `test_C_bridgeWithdrawal_adversarialRecipient_reentrancyMatrix` (0.0467 ETH real bridge withdrawal; lockbox −v + v/4, portal +v/4), `test_D_direct_reentrantTarget_matrix_and_strandedDonation` (53.47 ETH real fee-vault withdrawal; lockbox −v + 10 ETH, portal +20 ETH). Recipient/target code was substituted with `vm.etch`.

Confidence: high.

Reason it may be benign: every value-moving re-entry is funded by the callee's own received value.
