# PRIM-3106 — Portal trusts successful L1CDM return rather than checking messenger outcome mappings

**PRIM-ID:** PRIM-3106  
**Source contracts:** OptimismPortal2 v9; CrossDomainMessenger v9.  
**Exact functions:** `OptimismPortal2.finalizeWithdrawalTransactionExternalProof`; `CrossDomainMessenger.relayMessage`.  
**Trigger:** Messenger-sender withdrawal where the configured L1CDM target returns success but does not set `successfulMessages` or `failedMessages`.  
**Attacker-controlled inputs:** None sufficient in current production configuration. The locating test replaces L1CDM code with a successful return-bomb/no-op via `vm.etch`.  
**Required state:** Mature unfinalized messenger proof and a faulty/malicious messenger implementation.  
**State mutation:** Portal marks globally finalized and transfers value to L1CDM while neither genuine messenger mapping is written.  
**External calls:** Portal -> lockbox -> L1CDM.  
**Cross-contract dependency:** Portal interprets low-level call success as adequate evidence of messenger bookkeeping; it cannot inspect a return value because `relayMessage` returns none.  
**Broken or weakened assumption:** “Successful L1CDM call implies replay state was recorded.”  
**Candidate compositions:** Future privileged messenger upgrade bug; ResolvedDelegateProxy/AddressManager target corruption; any permissionless mechanism that can induce a success-without-bookkeeping messenger branch (none found).  
**Evidence:** Portal v9 `OptimismPortal2.sol:620-657`; messenger v9 `CrossDomainMessenger.sol:256-306`; mocked fork locator `test/AdversarialTargets.t.sol::test_mockedSuccessfulNoopMessenger_canStillProduceFinalizedNeither`. Real gas fuzz and real L1CDM paths found zero such outcomes.  
**Confidence:** High as a contract trust boundary; zero confidence in current permissionless production reachability.  
**Reason it may be benign:** Mocked-only condition; deployed L1CDM is governed and all reachable normal branches either revert or record a mapping. It is not a candidate.
