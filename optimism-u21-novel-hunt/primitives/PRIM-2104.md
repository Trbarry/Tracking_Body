PRIM-2104: Permissionless deterministic proxy-salt occupancy in OPCM Utils

Source contracts: OPContractsManagerUtils, Blueprint, OPContractsManagerV2, OPContractsManagerMigrator.

Exact functions: `OPContractsManagerUtils.loadOrDeployProxy` (`OPContractsManagerUtils.sol:225-302`), `computeSalt` (`:96-110`); `Blueprint.deployFrom` (`Blueprint.sol:118-134`).

Trigger: Directly call Utils with a failing source, a matching `PermittedProxyDeployment` instruction, chosen deployment args, and a normal ERC1967 proxy contract name.

Attacker-controlled inputs: Source, selector, ProxyAdmin, AddressManager, L2 chain ID, salt mixer, contract name, and permission array.

Required state: The computed CREATE2 address is unused. To occupy a future exact address, the attacker must know the future constructor admin and salt inputs.

State mutation: Deploys an uninitialized proxy at the Utils CREATE2 address, even when the supplied ProxyAdmin is owned by the production Safe. The attacker cannot upgrade it, but a second identical deployment collides and reverts.

External calls: Container blueprint getters, blueprint parsing, CREATE2; legacy proxy names additionally call ProxyAdmin and therefore fail without authority.

Cross-contract dependency: OPCM/Migrator also call the same Utils deployer. Migration derives salt input from `block.timestamp` and a fixed string; upgrade uses fixed `"salt mixer"`; new-chain deploy adds caller bytes but those bytes can be copied into a direct Utils call.

Broken or weakened assumption: CREATE2 address uniqueness does not imply only the intended OPCM entry point can occupy it.

Candidate compositions: Same-block migration front-running; fixed-salt predeployment for a future upgrade that must introduce a normal proxy such as ETHLockbox.

Evidence: N-fork test `test_utilsCanPermissionlesslyOccupyPredictedNormalProxySalt` deploys an ETHLockbox proxy using the exact migration salt shape and observes the second deployment revert. Source deployment is unauthenticated; only the later upgrade is authority-gated.

Confidence: High technically; low current-impact confidence.

Reason it may be benign: All four executed U21 chains already had their lockboxes, no current production target needing a fixed-salt proxy was identified, new-chain salt can be changed, and same-block migration squatting is a temporary/front-running DoS rather than demonstrated eligible impact.
