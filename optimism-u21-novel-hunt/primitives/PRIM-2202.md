PRIM-ID: PRIM-2202 — packed ASR dependency extension

Source contracts: `AnchorStateRegistry`, OZ `Initializable`.

Exact functions: `AnchorStateRegistry.initialize`, `paused`, `superchainConfig`.

Trigger: U21 reinitialization writes `ethLockbox` into slot 6 offset 12.

Attacker-controlled inputs: None in the deployed transition; the ProxyAdmin owner supplies the lockbox.

Required state: The upper 20 bytes of slot 6 are empty while the lower 12 bytes contain `respectedGameType` and `retirementTimestamp`.

State mutation: Fills only slot 6 bytes 12–31 with the lockbox address.

External calls: Later pause/config reads traverse ASR → ETHLockbox → SuperchainConfig.

Cross-contract dependency: Correct byte packing and a live, correctly administered lockbox are required for game validation pause semantics.

Broken or weakened assumption: A visually single “slot change” can mutate a new dependency while historical game type/timestamp bytes must remain invariant.

Candidate compositions: Future widening/repacking of either low field; wrong lockbox on a chain with a distinct respected game type; migration of legacy ASRs to a shared lockbox.

Evidence: v8 snapshot `AnchorStateRegistry.json:51-64`; v9 snapshot lines 51-70; `op-v9.0.0/.../AnchorStateRegistry.sol:50-59,94-138`; real slot-6 words for all four chains in `PRE_UPGRADE_STATE.json`/`POST_UPGRADE_STATE.json`; `StorageBoundaryTest.test_expectedDependencySlotsOnly`.

Confidence: High.

Reason it may be benign: Every high region was zero pre-upgrade, every low 96-bit region was bit-identical after, and each new address equals the intended per-chain lockbox (including Soneium type 5).
