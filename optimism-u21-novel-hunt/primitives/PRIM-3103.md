# PRIM-3103 — Withdrawal proofs are isolated per submitter, while the enumerable list admits duplicates

**PRIM-ID:** PRIM-3103  
**Source contracts:** OptimismPortal2 v8/v9.  
**Exact functions:** `proveWithdrawalTransaction`, `finalizeWithdrawalTransaction`, `finalizeWithdrawalTransactionExternalProof`, `numProofSubmitters`, `deleteProvenWithdrawal`.  
**Trigger:** Another address proves an existing withdrawal; the same address reproves it one or more times.  
**Attacker-controlled inputs:** Proof submitter address and timing; valid public proof calldata can be replayed.  
**Required state:** Valid withdrawal inclusion proof against a proper respected game.  
**State mutation:** `provenWithdrawals[hash][submitter]` is isolated. Reprove resets only that submitter's timestamp. Every prove appends the submitter again to `proofSubmitters[hash]`, including duplicates. Finalization remains global by withdrawal hash.  
**External calls:** DGF/game/ASR reads during prove and finalization.  
**Cross-contract dependency:** Game validity is common, proof maturity is submitter-specific, replay protection is global.  
**Broken or weakened assumption:** `proofSubmitters` is a history/multiset, not a unique set; its length is not a unique-submitter count.  
**Candidate compositions:** Any future onchain loop over this unbounded list; offchain accounting that treats length as cardinality; migration code that copies/iterates entries.  
**Evidence:** v9 `OptimismPortal2.sol:480-487,603-610,671-704,711-727,797-801`; exact N-1/N fork test `test/DifferentialWithdrawal.t.sol::test_exactNMinus1ToN_reproveBehaviorSame`; real post fixture test `test/PortalStateInvariants.t.sol::test_reproveIsolationAndFinalizationUniqueness_realProof`. Both versions append two entries for a second submitter's prove+reprove and preserve the original proof.  
**Confidence:** High.  
**Reason it may be benign:** Current finalization and deletion are O(1) mappings and do not iterate the list; replay remains globally blocked.
