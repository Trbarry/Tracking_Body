PRIM-ID: PRIM-2601 — privileged runtime feature transition changes treatment of pre-existing objects/liquidity
Source contracts: SystemConfig, OptimismPortal2
Exact functions: SystemConfig.setFeature; OptimismPortal2._isUsingCustomGasToken, depositTransaction, proveWithdrawalTransaction, finalizeWithdrawalTransactionExternalProof
Trigger: ProxyAdmin or ProxyAdmin owner toggles CUSTOM_GAS_TOKEN after deployment.
Attacker-controlled inputs: No permissionless feature input; after the privileged write, users supply deposits/withdrawals created under either state.
Required state: Initialized chain with cached Portal/lockbox and existing native-ETH liquidity.
State mutation: `isFeatureEnabled[CUSTOM_GAS_TOKEN]` changes immediately and is reversible.
External calls: Portal may lock/unlock ETH or revert before doing so.
Cross-contract dependency: Portal reads live SystemConfig state, while custody and pending messages/proofs predate the flag.
Broken or weakened assumption: Object creation mode is not snapshotted; execution uses current mode.
Candidate compositions: Any future permissionless/semi-privileged route to feature writes; L1/L2 CGT flag desynchronization; governance sequencing around outstanding withdrawals.
Evidence: `src/L1/SystemConfig.sol:528-568`; `src/L1/OptimismPortal2.sol:406-409,586-589,741-759,816-821`; fork test `FeatureStateMachineTest.test_cgtAndUnknownFeaturesRemainTwoWayToggles` against OP at block 26,430,859 with lockbox balance >182,000 ETH.
Confidence: High.
Reason it may be benign: Only PA/PA-owner can write; that role can upgrade the same proxies. Standard OPCM forbids enabling CGT during upgrades (`src/L1/opcm/OPContractsManagerV2.sol:998-1008`).
