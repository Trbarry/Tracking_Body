PRIM-ID: PRIM-2205 — heterogeneous initializer-byte offset across proxy variants

Source contracts: `L1CrossDomainMessenger`, `ResolvedDelegateProxy`, `OPContractsManagerUtils`, OZ `Initializable`.

Exact functions: Messenger `initialize`, OPCM `upgrade`, ResolvedDelegateProxy fallback.

Trigger: OPCM clears the caller-designated initializer byte before replay.

Attacker-controlled inputs: None permissionlessly; upgrade authority supplies the slot/offset metadata.

Required state: Standard targets keep `_initialized` at slot 0 offset 0; the messenger keeps it at slot 0 offset 20 after a 20-byte legacy spacer.

State mutation: A one-byte mask at offset 0 or 20.

External calls: ProxyAdmin → proxy → initializer.

Cross-contract dependency: Upgrade metadata must match inherited storage packing, which differs specifically because of the legacy proxy compatibility layout.

Broken or weakened assumption: One universal “initializer slot” is not sufficient even among the same U21 L1 bundle.

Candidate compositions: Future bundle generator supplies offset 0 for messenger, clearing a legacy spacer byte while leaving version 3 closed; or supplies offset 20 to a standard proxy and corrupts packed state.

Evidence: messenger snapshot `op-v9.0.0/.../snapshots/storageLayout/L1CrossDomainMessenger.json:1-28`; Resolved mappings `.../src/legacy/ResolvedDelegateProxy.sol:13-35`; mask logic `.../OPContractsManagerUtils.sol:356-372`; live implementation slot 0 `0x0000000000000000000000ff0000000000000000000000000000000000000000`; fork test pass.

Confidence: High.

Reason it may be benign: U21 used the correct offset: the messenger emitted `Initialized(3)`, retained all proxy metadata, and ended with version 3 closed.
