PRIM-ID: PRIM-0201
Title: Pause / guardian / SuperchainConfig resolution is now pinned in four independent storage pointers per chain

Source contracts: ETHLockbox (v2.0.0), AnchorStateRegistry (v4.0.0), DelayedWETH (v2.0.0), OptimismPortal2 (v6.1.0),
SystemConfig (v4.3.0), OPContractsManagerV2 / OPContractsManagerMigrator (v9.0.3)

Exact functions:
- `ETHLockbox.paused()` -> `superchainConfig.isLocalOrGlobalPaused(address(this))` (src/L1/ETHLockbox.sol:112-114), pointer `superchainConfig` slot 3 (:78)
- `AnchorStateRegistry.paused()/superchainConfig()/_assertOnlyGuardian()` -> `ethLockbox.*` (src/dispute/AnchorStateRegistry.sol:136-144, 375-379), pointer slot 6[12:32] (:59)
- `DelayedWETH.withdraw()/config()` -> `ethLockbox.*` (src/dispute/DelayedWETH.sol:74-76, 102), pointer slot 5 (:48)
- `OptimismPortal2.paused()/superchainConfig()/guardian()` -> `ethLockbox.*` (src/L1/OptimismPortal2.sol:306-330), pointer slot 63
- `SystemConfig.paused()` -> `portal.ethLockbox().paused()` (src/L1/SystemConfig.sol:574-576); `SystemConfig.guardian()` -> its own `superchainConfig` slot 108 (:580-582)
- L1CrossDomainMessenger / L1StandardBridge / L1ERC721Bridge `paused()` -> `systemConfig.paused()`

Trigger: none permissionless. The pointers are only written by `initialize` (ProxyAdmin / ProxyAdmin owner) and by
`OptimismPortal2.migrateToSharedDisputeGame` (ProxyAdmin owner).

Attacker-controlled inputs: none.

Required state: any state where the pointers disagree: `ASR.ethLockbox != portal.ethLockbox`, `DelayedWETH.ethLockbox !=
portal.ethLockbox`, or `ETHLockbox.superchainConfig != SystemConfig.superchainConfig`.

State mutation: none by itself.

External calls: ASR / DelayedWETH / Portal -> ETHLockbox -> SuperchainConfig (two extra hops compared with v8's
SystemConfig -> SuperchainConfig).

Cross-contract dependency: in v8 ASR and DelayedWETH derived everything through `systemConfig`, so they automatically
followed the portal's *current* lockbox (SystemConfig.paused() v8) and the SystemConfig's SuperchainConfig. In v9 each of
them stores its own lockbox pointer, and the lockbox stores its own SuperchainConfig pointer. Consistency now depends on
every flow that changes one pointer also re-initialising the other three:
- `OPContractsManagerV2._apply` re-inits Portal, ETHLockbox, DelayedWETH (the one in `SystemConfig.delayedWETH()`), ASR
  (the one in `portal.anchorStateRegistry()`) with the same lockbox (OPContractsManagerV2.sol:874-959).
- `OPContractsManagerMigrator.migrate` re-inits each chain's DelayedWETH and old ASR to the new shared lockbox
  (OPContractsManagerMigrator.sol:417-430, 545-555) and then repoints every non-first chain's
  `SystemConfig.delayedWETH` at chain[0]'s DelayedWETH (:229, :437-467). After that the non-first chains' own DelayedWETH
  proxies (Unichain `0x74ad145a..` with ~21.4 ETH of bonds today, if the planned OP Mainnet + Unichain migration runs with
  OP first by ascending chain id) are no longer reachable from any SystemConfig, so no later OPCM `upgrade` will ever
  re-initialise or upgrade them: they stay on the v9 implementation and on the lockbox pointer written by `migrate`.

Broken or weakened assumption: "a chain-specific pause (identifier = the chain's current lockbox) pauses every bond
withdrawal and every game-validity check of that chain". True at block 26433900 on all four chains (pointers consistent,
`test_newV9FieldsWiredOnAllFourChains`); true immediately after the planned `migrate`; no longer guaranteed for an orphaned
DelayedWETH / old ASR / old lockbox if the shared lockbox is ever replaced again or if a manual
`migrateToSharedDisputeGame` is used outside OPCM. The global pause (`address(0)`) always covers everything.

Candidate compositions:
- needs (a) a second lockbox change after `migrate` AND (b) an incident where the Guardian relies on the chain-specific
  identifier to stop `DelayedWETH.withdraw` of games still in flight on an orphaned DelayedWETH. Not attacker-triggerable.
- `ETHLockbox._authorizePortal` compares `portal.systemConfig().superchainConfig()` with the lockbox pointer once, at
  authorisation time (ETHLockbox.sol:227-228); a later SystemConfig re-init with another SuperchainConfig (privileged
  override `overrides.cfg.superchainConfig`) would desynchronise `SystemConfig.guardian()` from `portal.guardian()`.

Evidence:
- storage at N (POST_UPGRADE_STATE.json): OP `ETHLockbox[3] = 0x95703e09..`, `ASR[6] = 0x322b47ff..00000000688271ab00000009`,
  `DelayedWETH[5] = 0x322b47ff..`; same shape on Ink / Soneium / Unichain (U21_STORAGE_LAYOUT_DIFF.md §3.1).
- fork test `test_newV9FieldsWiredOnAllFourChains` (test/poc/lane02/U21StorageReinit.t.sol).

Confidence: high that the dependency structure is as described; low that it is ever exploitable.

Reason it may be benign: every path that writes a pointer is ProxyAdmin-owner only; OPCM keeps them consistent in the
documented `upgrade` and `migrate` flows; global pause is unaffected; DelayedWETH `hold`/`recover` remain available to the
ProxyAdmin owner regardless of pause wiring.
