# PRIM-2403 — Per-submitter proofs converge on one hash-global replay bit

`provenWithdrawals[withdrawalHash][submitter]` stores separate game/timestamp records, and each proof appends the submitter (`OptimismPortal2.sol:94-116,480-487`). Re-proving the same key overwrites the record and resets maturity. `deleteProvenWithdrawal` deletes only one submitter's proof after challenger victory or current-registry blacklist (`:707-728`); it does not clean the append-only submitter list.

Finalization is different: `checkWithdrawal` always consults the one `finalizedWithdrawals[withdrawalHash]` bit before validating the selected proof (`:671-704`). Thus alternate submitters, games, duplicate array entries, deletion/re-creation, and standard versus external-proof entry points cannot create distinct economic executions.

Fork evidence uses two real finalized type-9 games and two submitters. Finalization through submitter B executed once; submitter A then reverted `AlreadyFinalized` (`mirror/lane-24/tests/WithdrawalFinalization24.t.sol:478-495`). The pinned source suite tests the same global convergence (`test/L1/OptimismPortal2.t.sol:2357-2403`).

Deletion/re-proving can recover a usable proof but cannot clear the global replay bit. The stale `proofSubmitters` entries are an off-chain selection nuisance, not an on-chain replay primitive.
