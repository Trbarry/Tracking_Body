PRIM-ID: PRIM-1003 — Shared singletons re-pointed and re-initialized underneath in-flight game clones (DelayedWETH 1.5.1 -> 2.0.0, AnchorStateRegistry 3.9.0 -> 4.0.0), and re-run initializers that overwrite live config

OLD ASSUMPTION: a game clone's dependencies are fixed at creation. True for implementation, VM, prestate
(immutable args) — not for the DelayedWETH and AnchorStateRegistry *proxies*, whose implementation, pause
source and guardian source can be swapped while the clone holds bonds in them.

NEW U21 CONDITION: U21 upgraded both proxies under all in-flight games of OP Mainnet, Ink, Unichain (type 9,
SuperFaultDisputeGame 0.8.0, impl `0x19AF533C…` unchanged); Soneium (type 5, no bonds) only has the ASR swapped. `systemConfig` became a spacer
and a new `ethLockbox` pointer drives `paused()`, `superchainConfig()/config()` and the guardian check
(`DelayedWETH.sol:63,102`, `AnchorStateRegistry.sol:107,137`). Both were re-initialized through StorageSetter
inside the upgrade tx (DelayedWETH `_initialized` is 1 before and after although `initialize` ran again).
`AnchorStateRegistry.initialize` unconditionally writes `respectedGameType = _startingRespectedGameType`
(`:109`) and can clear `anchorGame`; `SystemConfig.initialize` re-emits BATCHER / FEE_SCALARS / GAS_LIMIT
`ConfigUpdate` events that L2 derivation consumes.

COMPOSITION POSSIBILITY: any future upgrade or the planned interop `migrate` re-runs these initializers
(`OPContractsManagerMigrator.sol:255-271,417-430`): the old ASR and each chain's old DelayedWETH are re-pointed
at the shared lockbox. A wrong argument there (not an attacker action) changes pause source, respected type or
L2 config for live state. Nothing here is reachable without the ProxyAdmin owner.

REQUIRED ATTACKER CONTROL: none available (all writes are ProxyAdmin/owner gated).

POSSIBLE IMPACT: bond freeze if a DelayedWETH were upgraded to 2.0.0 with `ethLockbox == 0` (`withdraw` would
call `paused()` on address(0)). Bond-only (Medium at best under the programme) — and not the deployed state.

Source contracts: `src/dispute/DelayedWETH.sol`, `src/dispute/AnchorStateRegistry.sol`,
`src/dispute/SuperFaultDisputeGame.sol`, `src/L1/SystemConfig.sol`, `src/L1/opcm/OPContractsManagerMigrator.sol`.
Exact functions: `DelayedWETH.initialize/withdraw/config`, `AnchorStateRegistry.initialize/paused/_assertOnlyGuardian`,
`SuperFaultDisputeGame.closeGame/claimCredit` (:966-1025), `SystemConfig.initialize` (:203-247).
Trigger: upgrade transaction (privileged).
Attacker-controlled inputs: none.
Required state: in-flight games holding WETH in the proxy.
State mutation: proxy slot 5 (DelayedWETH) / slot 6 high bytes (ASR) = lockbox; ETHLockbox slot 3 = SuperchainConfig.
External calls: game -> ASR.paused/isGameFinalized/setAnchorState/isGameProper, game -> WETH.unlock/withdraw,
WETH/ASR -> lockbox.paused -> SuperchainConfig.isLocalOrGlobalPaused.
Cross-contract dependency: lockbox must be non-zero and expose `paused()`, `superchainConfig()`, `guardian()`.
Broken or weakened assumption: immutability of a clone's environment.
Candidate compositions: (1) migration argument errors; (2) a chain upgraded to v9 DelayedWETH whose OPCM input
omits the lockbox; (3) guardian tooling still pausing the portal identifier (ineffective after U21).
Evidence:
- Storage N-1 vs post: DelayedWETH `0x1b6dbf05…` slot 5 `0 -> 0x322b47ff…`, impl `0xe440cc08… -> 0xf024e963…`;
  ASR `0x23B2C629…` slot 6 gains the lockbox in the top 20 bytes, `retirementTimestamp` 0x688271ab and
  `respectedGameType` 9 preserved; lockbox slot 3 `0 -> 0x95703e09…`.

  holding bonds (25 in progress, 29 resolved-not-closed, 13 closed-unclaimed; every 3rd of the last 210) all

- `gameArgs(9)` changed only in the prestate (`0x031ac6f1… -> 0x03e5a548…`); a pre-U21 clone still returns
  the old prestate, same VM `0xacc005dc…`, WETH and ASR.
Confidence: high.
Reason it may be benign: wiring is correct on all four chains, the game-facing ABI of both singletons is
unchanged, and every mutation is owner-gated.
