PRIM-ID: PRIM-0102
Title: SUPER_CANNON_KONA games on the pre-U21 absolute prestate stay in flight, respected and resolvable after U21

Source contracts: `src/dispute/DisputeGameFactory.sol` (v1.6.1), `src/dispute/SuperFaultDisputeGame.sol` (v0.8.0, impl `0x19AF533Cc2A2A55786DCB8672aA5717e64213208`, unchanged by U21), `src/dispute/AnchorStateRegistry.sol`, `src/L1/opcm/OPContractsManagerV2.sol:964-987`.

Exact functions: `DisputeGameFactory.setImplementation(gameType, impl, args)` (only replaces `gameArgs[9]` for future clones), game `absolutePrestate()` (immutable clone arg), `AnchorStateRegistry.setAnchorState`, `OptimismPortal2.proveWithdrawalTransaction`.

Trigger: none needed; any participant can keep playing (`move`, `step`, `resolveClaim`, `resolve`) games created before block 26430859.

Attacker-controlled inputs: moves and steps in games whose VM prestate is `0x031ac6f15c19010da258f5cb633ef6ca9318c2d0f244bea6b2045ce6b790e1df` (kona-client before v1.9.0) instead of the new `0x03e5a54835d39c1d83b198314473e1f111c3539c04f65c3e8a9b8ccebe3737c9`.

Required state: a type-9 game created before the upgrade. On OP Mainnet indices up to 21377 (created 1794870155, 21 minutes before the upgrade at 1794871439). Verified IN_PROGRESS at 26433900: 21370, 21376, 21377; from the creation rate (about one per hour) and the 302400 s clock, roughly 80 more are in flight. Ink and Unichain had the same prestate swap and are presumably in the same situation (their games were not sampled).

State mutation: none by U21 on those games; they later update `anchorGame` and back withdrawal proofs.

External calls: old clones call the upgraded ASR v4.0.0 and DelayedWETH v2.0.0 through the same proxies.

Cross-contract dependency: `retirementTimestamp` is not bumped by the upgrade, `respectedGameType` stays 9, so `wasRespectedGameTypeWhenCreated` is true for old-prestate and new-prestate games alike.

Broken or weakened assumption: "the new prestate is what secures the chain after U21". For at least 3.5 days (clock) + 3.5 days (finality airgap) the old program decides games, and those games remain valid proof anchors afterwards.

Candidate compositions: if the kona v1.9.0 prestate fixes a soundness bug of the old program, that bug stays exploitable in every old game still IN_PROGRESS (a wrong claim cannot be newly created on the old prestate after U21, but an existing claim tree can still be played). Needs the kona diff; not analysed in this lane.

Evidence:
- `cast call <game> "absolutePrestate()(bytes32)"`: indices 21370/21376/21377 -> `0x031ac6f1...`; 21378/21379/21388 -> `0x03e5a548...`; all `status() == 0`, `wasRespectedGameTypeWhenCreated() == true` (`l1`).
- OP anchor game after U21 `0x55A5CFd4270340b3822BB9D8eebdb450ac206f95`: created 1794299939, resolved 1794602387, old prestate - accepted by ASR v4.0.0 between N and 26433900.
- U21 notice: "Keep the Upgrade 20 prestate file in place so op-challenger can finish games created before the upgrade."

Confidence: high (state), unknown (impact).

Reason it may be benign: intended and documented; honest challengers run both prestates; no evidence here that the old prestate is unsound.
