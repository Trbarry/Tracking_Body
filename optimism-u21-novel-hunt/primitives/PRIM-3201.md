# PRIM-3201 — Permissionlessly unstable validator-only zero-balance assertions

PRIM-ID: PRIM-3201

Source contracts: `OPContractsManagerMigrationValidator`, `OptimismPortal2`, EVM account semantics.

Exact functions: `assertRetiredContractsClean`, `donateETH`; force-send through a constructor `SELFDESTRUCT`.

Trigger: After a migration validation observes a zero portal or retired-lockbox balance, any account sends ETH with `donateETH`, or creates a funded contract whose constructor self-destructs to that address.

Attacker-controlled inputs: Destination portal/lockbox and donated amount.

Required state: Any deployed portal; no role, authorization, or protocol feature is required.

State mutation: The destination account balance becomes nonzero. No Optimism contract storage changes.

External calls: `donateETH` receives value; the constructor force-send does not invoke destination code.

Cross-contract dependency: The validator treats `address(portal).balance == 0` and, conditionally, `address(legacyLockbox).balance == 0` as post-migration invariants (`OPContractsManagerMigrationValidator.sol:559-567`). The production contracts cannot enforce those invariants against forced ETH.

Broken or weakened assumption: A successful off-chain validation does not make either zero-balance condition stable.

Candidate compositions: A workflow that treats a later validator failure as proof of incomplete migration; a future sweep/accounting path that assumes retired accounts cannot receive ETH.

Evidence: `mirror/lane-32/test/NegativeSpace.t.sol::test_siblingValuePaths_unauthorizedLockAndReceiveRevert_butDonateSucceeds` and `::test_validatorZeroBalanceCanBeInvalidatedAfterValidationByForceSend`, both against block 26433900 deployed bytecode. Unauthorized `lockETH` and `receiveLiquidity` each revert `ETHLockbox_Unauthorized`, while both permissionless value paths succeed.

Confidence: High for the primitive; high that it is currently benign.

Reason it may be benign: The donor supplies the ETH, migration does not rely on a persistent validator attestation, portal-held ETH is not the withdrawal liquidity source after lockbox activation, and no theft/freeze amplification was found.
