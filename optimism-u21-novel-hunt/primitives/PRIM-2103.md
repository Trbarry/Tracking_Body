PRIM-2103: DGF configuration updates bifurcate old and new game prestates

Source contracts: DisputeGameFactory, AnchorStateRegistry, SuperFaultDisputeGame.

Exact functions: `DisputeGameFactory.setImplementation`, `create` (`DisputeGameFactory.sol:142-225,298-317`); `AnchorStateRegistry.isGameRegistered/isGameRespected/isGameProper` (`AnchorStateRegistry.sol:227-307`).

Trigger: Owner updates `gameArgs[type 9]`; any user later creates a new type-9 game.

Attacker-controlled inputs: Root claim and extraData for game creation, plus the required 0.08 ETH bond. The prestate is not attacker-selected; it is snapshotted from factory gameArgs into clone immutable args.

Required state: A type-9 game exists before the configuration update and remains registered, unretired, and respected.

State mutation: Factory type-9 args changed from `0x031ac6f15c19010da258f5cb633ef6ca9318c2d0f244bea6b2045ce6b790e1df` to `0x03e5a54835d39c1d83b198314473e1f111c3539c04f65c3e8a9b8ccebe3737c9` on OP, Ink, and Unichain. Existing clones retain the old prestate; later clones use the new one.

External calls: Game creation clones and initializes the configured implementation; ASR later queries the clone and DGF registration mapping.

Cross-contract dependency: ASR uses the game’s creation-time `wasRespectedGameTypeWhenCreated()` and preserved retirement timestamp, so a factory prestate update alone does not invalidate old games.

Broken or weakened assumption: Updating the factory prestate does not retire or reinterpret in-flight games.

Candidate compositions: Any soundness defect specific to the old prestate can remain withdrawal-relevant through pre-upgrade in-flight games; future migration must account for both old and new populations.

Evidence: `dispute-state.json` records pre-U21 games OP `0x675E...00d10`, Ink `0x40be...942cc`, and Unichain `0x3073...a68d8` as registered/respected/unretired/proper at pre and post, with old prestate; every later type-9 clone has the new prestate.

Confidence: High for the bifurcation; no claim that either prestate is unsound.

Reason it may be benign: Preserving in-flight games is deliberate and no defect in the old prestate was established.
