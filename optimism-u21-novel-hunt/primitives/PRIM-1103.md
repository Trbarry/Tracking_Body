PRIM-ID: PRIM-1103 — The relay-reserve defect that U21 fixes on L1 is still live in the (un-upgraded) L2CrossDomainMessenger 2.2.1: a 20–60 KB L1→L2 message whose target exhausts its gas is recorded in NEITHER mapping (deposit tx reverts), unreplayable, ETH stranded

Source contracts:
- L2CrossDomainMessenger `0x4200000000000000000000000000000000000007` on OP Mainnet, `version() = "2.2.1"`
  (read on fork `l2` @ 159654093): pre-U21 `CrossDomainMessenger.relayMessage(… bytes calldata _message)`,
  `RELAY_RESERVED_GAS = 40000`, `RELAY_GAS_CHECK_BUFFER = 5000` (cast reads)
- L1CrossDomainMessenger v2.13.0 (`baseGas` for the L1→L2 direction: same values on v8 and v9 —
  differential D1: `cdm.baseGas(*)` identical, `RELAY_*` getters 200000/40000/40000/5000)
- v8 baseline for the mirror-image L1 behaviour: L1CDM 2.11.1 + portal 5.8.0 on `l1pre`

Exact functions:
- v8-style `relayMessage`: `SafeCall.call(_target, gasleft() - RELAY_RESERVED_GAS, _value, _message)`
  (op-v8.0.0 src/universal/CrossDomainMessenger.sol:298) — `gasleft()` is read BEFORE the
  `calldata → memory` copy of `_message`, so the copy (memory expansion + CALLDATACOPY) and the
  CALL's own charges are paid out of the 40 000 reserve. A target that consumes everything forwarded
  leaves less than the ~22 k needed for `failedMessages[hash] = true` + event → out of gas → the
  whole relay reverts.
- v9 fix (L1 only): `bytes memory _message` (op-v9.0.0 src/universal/CrossDomainMessenger.sol:215),
  `L1_RELAY_RESERVED_GAS = 135_000` (src/libraries/GasConstants.sol:60), portal revert
  `OptimismPortal_L1CDMCallFailed` (src/L1/OptimismPortal2.sol:651-653). Documented in the U21
  notice ("copies the payload into memory before its gas check so the copy no longer uses up the
  reserved gas"; "Upgrade 21 has no L2 hardfork").

Trigger:
`L1CrossDomainMessenger.sendMessage{value: v}(target, message, minGasLimit)` with a 20–60 KB message
to an L2 target that runs out of gas (INVALID / OOG / minGasLimit under-specified for the target).
The L2 deposit transaction's gas limit is fixed by the protocol (`baseGas`), nobody picks it.

Attacker-controlled inputs: message size, target, value (sender side); or — for a third party —
whatever makes the victim's L2 handler exhaust gas (state-dependent gas cost).

Required state: none (live at the pin).

State mutation (executed, `test/poc/L2RelayGas.t.sol`, output `evidence/lane11/l2-relay-gas.txt`):

| payload | len | burn target, value 0 | burn target, 1 ETH | honest target, 1 ETH |
|---|---|---|---|---|
| non-zero | ≤ 10 000 | FAILED (replayable) | FAILED (replayable) | RELAYED |
| non-zero | 20 000 / 30 000 | FAILED (replayable) | **relay tx reverts, neither recorded** | RELAYED |
| non-zero | 40 000 / 60 000 | **reverts, neither** | **reverts, neither** | RELAYED |
| non-zero | 90 000 / 119 000 | FAILED (replayable) | FAILED (replayable) | RELAYED |
| all-zero | 20 000 / 30 000 | FAILED | **reverts, neither** | RELAYED |
| all-zero | 40 000 | **reverts, neither** | **reverts, neither** | RELAYED |
| all-zero | ≥ 60 000 | FAILED | FAILED | RELAYED |

(same for minGasLimit 0 and 200 000; above ~60–90 KB the 40 gas/byte floor in `baseGas` makes the
frame large enough that the EIP-150 1/64 remainder covers the bookkeeping.)
When the deposit transaction reverts, its mint stays on the aliased L1CDM address
`0x36BDE71C97B33Cc4729cf772aE268934f7AB70B2`; the message hash is in neither `successfulMessages`
nor `failedMessages`, so `relayMessage` can never be called for it again.

Mirror on L1 under v8 (`evidence/lane11/injected-gas-l1pre-S4.json`, HARNESS-injected withdrawals, real
bytecode): burn target, legacy-formula gasLimit, 35–105 KB → `FINALIZED_NEITHER` for every gas value
from the portal's minimum up to ≈1.88–2.6 M (e.g. 50 KB + 1 ETH: NEITHER for gas ∈ [1 489 079,
2 055 075], FAILED from 2 068 000; value re-locked in the lockbox = lost to the user). Under v9 the
same 26 cases are `FINALIZED_FAILEDMSG` at every probed gas value (0 NEITHER in 18 039 probes; v8: 1 934 NEITHER in 18 041).

External calls: aliased L1CDM (deposit) → L2CDM proxy → impl → target.

Cross-contract dependency: L1 `baseGas` (REMOTE_* = L2 budgets, unchanged) ↔ L2 relay reserve
(unchanged, too small once the payload copy is charged to it).

Broken or weakened assumption:
"A message whose target fails is recorded in `failedMessages` and can be replayed" does not hold on
L2 for 20–60 KB messages with a gas-exhausting target; U21 restores it on L1 only.

Candidate compositions:
- any production L1→L2 flow that sends ≥ 20 KB payloads through the messenger (governance / upgrade
  bundles, batched calls, large `bytes` bridging) to a handler whose gas use a third party can
  inflate → permanent loss instead of a replayable failure;
- U21's L2ContractsManager / future L2 bundle: until it runs, L1 (fixed) and L2 (unfixed) disagree —
  lanes on L2CM should check that the L2 messenger really gets the `bytes memory` version.

Evidence:
- `test/poc/L2RelayGas.t.sol::test_l2_relay_gas_matrix` (fork `l2`, real L2CDM bytecode; the only
  cheat is `vm.prank(aliased L1CDM)`, which is how every L1→L2 message arrives)
- `test/poc/InjectedGas.t.sol` Set 4 on `l1pre` vs `l1`
- cast: `cast call 0x42…07 "version()(string)" --rpc-url l2` → `2.2.1`; `RELAY_RESERVED_GAS()` → 40000

Confidence: high for the measured behaviour. Frame-gas model for a deposit: `baseGas − 21000 −
16/4 gas per non-zero/zero calldata byte` (deposit intrinsic gas); not validated against a real
derived deposit of that size.

Reason it may be benign:
Needs a target that exhausts gas (REVERT refunds gas and stays replayable) and a 20–60 KB message —
sender-side error in the common case; LANE_CONTEXT §6 lists large-calldata / specific-gas
cross-chain message griefing as not-a-finding; the L1 half is the documented U21 fix, so the L2
half is very likely known and scheduled. Score if promoted as a candidate:
+2 reproduced on real bytecode, +1 deterministic, −4 documented class, −2 victim self-harm,
−3 no directly eligible impact without a third-party gas-inflation vector = **−4** → not a candidate.
