# PRIM-2404 — Proof validity is re-evaluated against mutable current configuration

## Guard inventory

A proof captures only `(game,timestamp)`. Proving reads current Portal pause, feature flags, current lockbox target safety, current ASR/factory registration, current blacklist/retirement/pause, and the game's creation-time respected bit (`OptimismPortal2.sol:390-435`; `AnchorStateRegistry.sol:215-308`).

Finalization later re-reads:

- current ETHLockbox pause and current custom-gas-token feature (`OptimismPortal2.sol:583-589`);
- current lockbox address for unsafe-target rejection (`:598-600,845-849`);
- current Portal `anchorStateRegistry`, whose `isGameClaimValid` re-evaluates factory registration, blacklist, retirement, ASR pause, creation-time respected status, resolution/finality, and defender victory (`:671-704`; `AnchorStateRegistry.sol:286-353`).

The respected *type setting* is not directly re-read: `isGameRespected` asks the game for `wasRespectedGameTypeWhenCreated()` (`AnchorStateRegistry.sol:239-247`). Blacklist and retirement are current mutable values. Swapping the ASR pointer makes old proofs invalid by design, but the unchanged withdrawal hash can be re-proven against the new registry; proof overwrite is expressly supported (`OptimismPortal2.sol:480-487`).

## Result

No permissionless permanent loss or replay was found. Mutable invalidation either pauses/defers finalization or requires re-proof. A privileged migration could make a previously safe target equal the new lockbox or strand old proof metadata, but that is operator-controlled and does not defeat hash-global replay protection.
