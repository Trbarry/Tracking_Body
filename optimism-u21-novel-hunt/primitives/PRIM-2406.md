# PRIM-2406 — v8 proof and messenger replay state survive U21 unchanged

The v8 and v9 storage-layout snapshots for both `OptimismPortal2` and `L1CrossDomainMessenger` are byte-identical (SHA-256 values recorded in `SOURCE_DIFF_NOTES.md`). Real state confirms continuity.

## Real proof

Withdrawal `0xcb4d…a1651d`, proven before U21 in tx `0xe7d3…c089`, retained the same game `0x8651…e5fe`, timestamp `1794861023`, submitter count 1, and `finalized=false` at N-1, N, and the later pinned block. The full struct is recorded in `REAL_WITHDRAWAL_EVIDENCE.md`; the fork assertion is `WithdrawalFinalization24.t.sol:524-535`.

## Real failed message

Message `0x9546…11312` emitted `FailedRelayedMessage` under v8 at block 26,385,051. At N-1, N, and post-U21 it remained `failed=true, successful=false`. Its exact v8 calldata was called through deployed v9 messenger code on the private fork: the transaction succeeded at the messenger level, emitted `FailedRelayedMessage` again because the application still rejected it, and retained a replay path. The in-process reproduction is `WithdrawalFinalization24.t.sol:455-476`.

A separate storage-continuity test installs the exact one-bit v8 failed state at unchanged slot 206, replays successfully under v9, and proves the persistent failed bit cannot bypass `successfulMessages` (`:430-453`).

No cross-version double execution or storage reinterpretation was found.
