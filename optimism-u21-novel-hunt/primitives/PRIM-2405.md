# PRIM-2405 — Conservative pre-Amsterdam new-account reserve

v9 adds `NEW_ACCOUNT_STATE_GAS = 183,600` and supplies it as reserved gas only when value is nonzero and `EXTCODEHASH(target)==0` (`SafeCall.sol:7-9,119-135`). A truly nonexistent account has codehash zero; an existing nonce/balance account with empty code has `keccak256("")` and receives no extra reserve.

At the pinned mainnet fork Amsterdam/EIP-8037 is not active. The reserve is therefore conservative today: a near-threshold finalization can revert `SafeCall: Not enough gas` even though today's CALL might fit. Because the revert unwinds the earlier finalized bit and Lockbox unlock, it preserves the legitimate replay path; it does not create finalized non-delivery.

Fork tests sent 1 ETH successfully to both:

- untouched `0x101` (balance 0, nonce 0, no code, `EXTCODEHASH=0`), and
- a funded/code-empty account (`EXTCODEHASH=keccak256("")`).

See `mirror/lane-24/tests/WithdrawalFinalization24.t.sol:192-224`. Amsterdam behavior is not locally reproducible and no activation claim is made. The v9 gas budget comments describe the future state-gas assumptions (`GasConstants.sol:23-25,39-60,74-78`).
