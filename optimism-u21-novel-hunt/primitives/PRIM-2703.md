# PRIM-2703

PRIM-ID: PRIM-2703 — respect is snapshotted at game creation and survives later implementation/type removal

Source contracts: `FaultDisputeGame`, `SuperFaultDisputeGame`, `AnchorStateRegistry`, `DisputeGameFactory`.

Exact functions: game `initialize`; `AnchorStateRegistry.isGameRespected`, `isGameRetired`, `isGameClaimValid`; factory `setImplementation`.

Trigger: Create a game while its type is respected, then change the respected type and/or set that type's factory implementation to zero.

Attacker-controlled inputs: For permissionless game types, the proposal and bond at creation time.

Required state: The game was created strictly after `retirementTimestamp`, remains registered/unblacklisted, resolves `DEFENDER_WINS`, and passes the finality delay.

State mutation: The old game remains usable for proof finalization and may become the shared anchor despite new games of its type being disabled.

External calls: Portal calls current ASR at finalization; ASR calls the historical game snapshot/status.

Cross-contract dependency: Current factory implementation registration controls new creation, while the factory UUID mapping and per-game respect snapshot control historical validity.

Broken or weakened assumption: “Unset now” does not mean “invalid now.”

Candidate compositions: Search the non-retired historical set for a defender-wins game whose root was semantically invalid, or a game spanning a security-model/prestate transition.

Evidence: `packages/contracts-bedrock/src/dispute/AnchorStateRegistry.sol:239-263,310-353`; `.../FaultDisputeGame.sol:317-319`; on-chain index 9828 (`0x5812...11bd`) is type 0, factory type-0 implementation is zero, yet `isGameClaimValid == true`; fork test `HistoricalGamesTest.test_oldUnsetTypeCanRemainClaimValid`.

Confidence: High.

Reason it may be benign: This is deliberate snapshot behavior and the concrete boundary/transition samples checked in lane 27 all matched canonical L2 output roots.
