PRIM-ID: PRIM-2204 — dynamic gameArgs payload mutation behind a stable mapping head

Source contracts: `DisputeGameFactory`, `LibGameArgs`.

Exact functions: `DisputeGameFactory.setImplementation(GameType,IDisputeGame,bytes)`, `gameArgs`, dispute-game creation/clone initialization.

Trigger: Owner configures a game type with the same implementation but new packed constructor arguments.

Attacker-controlled inputs: Owner-only configuration; permissionless users later create games using the configured template.

Required state: A nonempty dynamic `bytes` value at mapping base slot 105.

State mutation: The mapping head/length can remain unchanged while tail words at `keccak256(mappingEntrySlot)` change semantic fields.

External calls: Future game creation clones the implementation and consumes these arguments.

Cross-contract dependency: DGF implementation, `LibGameArgs` byte offsets, ASR/WETH addresses, VM, prestate, proposer, and respected type must agree.

Broken or weakened assumption: A linear first-N-slots diff is insufficient to prove configuration stability for dynamic mapping values.

Candidate compositions: Same implementation with incompatible argument schema; prestate drift on only some chains; proposer change on a permissioned type.

Evidence: DGF snapshot slots 101/102/105 at `op-v9.0.0/.../snapshots/storageLayout/DisputeGameFactory.json:37-70`; setters `.../DisputeGameFactory.sol:298-327`; schema `.../LibGameArgs.sol:9-23,61-103,116-142`; exact live values in `DGF_MAPPING_DIFF.md`.

Confidence: High.

Reason it may be benign: U21 values decode cleanly, only intended fields changed, implementations/bonds stayed constant, Soneium kept type 5, and arguments were stable through the later block.
