# PRIM-3202 — Asymmetric deployed messenger gas budgets across the upgrade boundary

PRIM-ID: PRIM-3202

Source contracts: `L1CrossDomainMessenger`, `CrossDomainMessenger`, `SafeCall`, `OptimismPortal2`.

Exact functions: `relayMessage`, `baseGas`, `_localRelayReservedGas`, `_localRelayGasCheckBuffer`, `callWithMinGas`, `finalizeWithdrawalTransactionExternalProof`.

Trigger: Relay an L2-to-L1 message after only the L1 messenger has moved to the v9 chain-local gas-budget implementation.

Attacker-controlled inputs: Message bytes, minimum gas, target, value, and top-level finalization gas subject to normal proof rules.

Required state: A valid proven messenger withdrawal.

State mutation: A successful relay marks the message successful. Insufficient execution gas leaves it retryable because the portal now reverts failed L2-messenger withdrawals.

External calls: Portal to L1 messenger, then L1 messenger to message target.

Cross-contract dependency: v9 L1 uses local reserve/buffer values of 135,000/15,000 while the public getters and `baseGas` expose the remote L2 40,000/5,000 budget (`L1CrossDomainMessenger.sol:43-74,117-152`; `CrossDomainMessenger.sol:259-285`). Live L2 still exposes the v8-style 40,000/5,000 values.

Broken or weakened assumption: The identically named public gas constants no longer describe the L1 relay's local execution reserve.

Candidate compositions: Future Amsterdam new-account state gas plus a value-bearing messenger target; off-chain estimators that interpret the public getter as the local reserve; mixed-version L1/L2 rollouts.

Evidence: `mirror/lane-32/test/NegativeSpace.t.sol::test_liveL1AndL2MessengerGasBudgetsExposeAsymmetricUpgrade`; v9 `SafeCall.sol:9,120-131`; portal failure handling at `OptimismPortal2.sol:621-652`.

Confidence: High for deployed asymmetry, medium for future-fork behavior, low for present impact.

Reason it may be benign: Today the extra accounting is conservative; callers can supply more top-level gas; and a failed messenger call rolls back finalization so the withdrawal can be retried. Amsterdam semantics are not active on the pinned mainnet fork.
