# PRIM-2705

PRIM-ID: PRIM-2705 — planned migration atomically cuts portals over to a fresh shared proof domain

Source contracts: `OPContractsManagerV2`, `OPContractsManagerMigrator`, `OptimismPortal2`, `AnchorStateRegistry`.

Exact functions: `OPContractsManagerV2.migrate`; migrator `migrate`, `_validateChainSystemConfigs`, `_migratePortal`; portal `migrateToSharedDisputeGame`, `checkWithdrawal`.

Trigger: The common ProxyAdmin-owner Safe delegatecalls the release OPCM with OP Mainnet and Unichain configs.

Attacker-controlled inputs: No migration inputs permissionlessly; an attacker can only pre-position ordinary games/proofs/funds before governance execution.

Required state: Both chains remain on release 9.0.3, share SuperchainConfig and ProxyAdmin owner, have distinct ascending IDs, are unpaused, and have INTEROP disabled.

State mutation: Deploy/init fresh shared lockbox, DGF, and ASR; authorize/switch both portals; sweep liquidity; clear old DGF implementations; point old pause dependencies at the new lockbox; register shared super games.

External calls: OPCM/migrator to both ProxyAdmins, SystemConfigs, portals, lockboxes, ASRs and factories.

Cross-contract dependency: Finalization checks the portal's current ASR, so stored pre-migration proofs reference games outside the new factory domain and become invalid (documented behavior).

Broken or weakened assumption: Proof validity is tied to the current portal registry, not frozen at proof time.

Candidate compositions: Pre-positioned state in old DelayedWETH/lockboxes, predictable proxy addresses, or proof records that a partial cutover might accidentally preserve.

Evidence: `packages/contracts-bedrock/src/L1/opcm/OPContractsManagerV2.sol:278-313`; `.../OPContractsManagerMigrator.sol:129-285,287-410,475-555`; `.../OptimismPortal2.sol:528-572,671-704`; current-state matrix in `mirror/lane-27/MIGRATION_MODEL.md`.

Confidence: High.

Reason it may be benign: The invalidation is explicitly documented, all relevant mutations occur in one transaction, and the deployed-address salt/deployer cannot be occupied by a permissionless actor.
