PRIM-ID: PRIM-1204 — pause coverage after U21: one live identifier per chain, every other address is dead, and what the pause does not stop

Source contracts: src/L1/SuperchainConfig.sol, src/L1/ETHLockbox.sol, src/L1/OptimismPortal2.sol, src/L1/SystemConfig.sol,
  src/dispute/AnchorStateRegistry.sol, src/dispute/DelayedWETH.sol (v9 @ ba6fcadb); legacy DelayedWETH proxies
  0xE497B094d6DbB3D5E4CaAc9a14696D7572588d14 (v1.0.0), 0x82511d494B5C942BE57498a70Fdd7184Ee33B975 (v1.1.0),
  0x323dFC63c9B83CB83f40325AaB74b245937cbdF0 (v1.3.0).

Exact functions: SuperchainConfig.pause(address) (L81-94), paused(address) (L143-147), isLocalOrGlobalPaused (L152-154);
  ETHLockbox.paused (L112-114); OptimismPortal2.paused (L306-308); SystemConfig.paused (L574-576);
  AnchorStateRegistry.paused (L136-138); DelayedWETH.withdraw (L101-102); OptimismPortal2.deleteProvenWithdrawal (L711-728).

Trigger: Guardian calls `SuperchainConfig.pause(identifier)`.

Attacker-controlled inputs: none (which entry points remain usable during a pause).

Required state: n/a.

State mutation (measured, OP Mainnet, Guardian pranked — a pause is a state production can be in):
  identifier = ETHLockbox 0x322b47Ff…  -> portal, SystemConfig, ASR, L1CDM, L1StandardBridge, L1ERC721Bridge, lockbox
                                          all report paused; DelayedWETH v2.0.0 `withdraw` reverts "contract is paused"
  identifier = address(0)             -> same, plus the three legacy DelayedWETH proxies
  identifier = portal / SystemConfig / ASR / L1CDM address -> nothing is paused (pause recorded in SuperchainConfig,
                                          consulted by no contract)
  Legacy DelayedWETH proxies (0.16 / 0.08 / 0.08 ETH of old bonds) read the argument-less
  `SuperchainConfig.paused()` == `paused(address(0))`: a lockbox-identifier pause does not reach them.

  Not stopped by any pause: `depositTransaction` / `lockETH` (ETH keeps entering), `donateETH`,
  `deleteProvenWithdrawal` (new in v9), `DisputeGameFactory.create`, game moves and `resolve`,
  `DelayedWETH.unlock`, messenger and bridge deposits.

External calls: view chain portal -> lockbox -> SuperchainConfig; SystemConfig -> portal -> lockbox -> SuperchainConfig.

Cross-contract dependency: SuperchainConfig `pauseTimestamps[identifier]`; the identifier is whatever
  `portal.ethLockbox()` returns.

Broken or weakened assumption: none in the contracts. Operationally: a pause issued with the pre-U21 mental model
  ("the portal address identifies the chain") succeeds on chain, emits `Paused(portal)` and pauses nothing; and
  `pause()` refuses to run again for that identifier until it is unpaused (`SuperchainConfig_AlreadyPaused`, L87-89).
  The notice tells operators to switch tooling; the contracts do not help them notice a miss.

Candidate compositions: incident response racing an attacker (wrong identifier costs a transaction round trip);
  monitoring that keys on `Paused(address)` with the portal address; the old-bond dust in legacy DelayedWETH during a
  chain-specific pause.

Evidence: test/poc/lane12/Lane12.t.sol::test_pause_lockboxIdentifier_pausesEverything,
  test_pause_globalIdentifier_pausesEverything, test_pause_portalOrSystemConfigIdentifier_pausesNothing,
  test_pause_legacyDelayedWETH_onlyGlobalPauseReachesThem, test_pause_scope (deposit of 1 ETH accepted while paused,
  finalize reverts `OptimismPortal_CallPaused`), test_R06_delete_afterBlacklist_permissionless_evenWhenPaused.
  Legacy proxy balances / versions: evidence/lane12/lane12-cast-evidence.txt §3.

Confidence: high.

Reason it may be benign: all four upgraded chains already used the lockbox identifier before U21 (ETH_LOCKBOX was true
  at block 26430858), so U21 changed no effective identifier for them; the dead-identifier case is operator error;
  the legacy escrows hold 0.32 ETH in total and predate U21.
