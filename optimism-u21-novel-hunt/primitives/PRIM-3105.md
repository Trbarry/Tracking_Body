# PRIM-3105 — Exact upgrade boundary introduces calldata-proportional deposit gas regression

**PRIM-ID:** PRIM-3105  
**Source contracts:** Deployed OptimismPortal2 v8/v9 bytecode; source `depositTransaction` and resource metering.  
**Exact functions:** `OptimismPortal2.depositTransaction`.  
**Trigger:** Permissionless deposit with increasingly large calldata up to 120,000 bytes.  
**Attacker-controlled inputs:** Data length/content, L2 gas limit, deposit value/target.  
**Required state:** Ordinary unpaused OP portal at exact N-1 or N.  
**State mutation:** Same `TransactionDeposited` event and same custody behavior on both versions.  
**External calls:** Lockbox only when `msg.value > 0`; measured curve used zero value.  
**Cross-contract dependency:** Resource metering reads SystemConfig, but minimum limit and acceptance were equal on both forks.  
**Broken or weakened assumption:** Deployment upgrade was not gas-neutral for otherwise identical large deposits.  
**Candidate compositions:** Relayer/user fixed L1 gas caps near the boundary; block-level calldata batches.  
**Evidence:** v8 `/home/user/ethereum-optimism/op-v8.0.0/packages/contracts-bedrock/src/L1/OptimismPortal2.sol:684-738`; v9 `/home/user/ethereum-optimism/op-v9.0.0/packages/contracts-bedrock/src/L1/OptimismPortal2.sol:741-795`; `test/DepositDifferential.t.sol`. Warmed curve N-N-1: -3,395 (0 B), +2,718 (256 B), +26,123 (4,096 B), +200,022 (32,768 B), +729,397 (120,000 B). Separate isolated 120k runs were 5,194,026 vs 5,635,990.  
**Confidence:** High that deployed gas differs; low on root cause and no eligible impact.  
**Reason it may be benign:** Semantics, selectors, event digest, limits, and balances match; large-calldata/specific-gas griefing is explicitly suppressed.
