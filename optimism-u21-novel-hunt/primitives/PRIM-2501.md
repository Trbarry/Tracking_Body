PRIM-ID: PRIM-2501
Source contracts: `OptimismPortal2`, `AnchorStateRegistry`, all deployed dispute-game families.
Exact functions: `OptimismPortal2.deleteProvenWithdrawal`; `AnchorStateRegistry.isGameBlacklisted`; game `status` and `resolve`.
Trigger: Any caller supplies a withdrawal hash and any proof-submitter address whose stored proof game is `CHALLENGER_WINS` or blacklisted.
Attacker-controlled inputs: Withdrawal hash, proof-submitter address, caller identity, gas.
Required state: Nonzero stored proof timestamp and either terminal challenger status or the exact game address permanently blacklisted.
State mutation: Deletes only `provenWithdrawals[hash][submitter]`; does not change finalization replay protection or the submitter array.
External calls: `status()` on the stored game first; if it is not challenger-wins, `anchorStateRegistry.isGameBlacklisted(game)`.
Cross-contract dependency: Game status semantics and the ASR blacklist's monotonicity.
Broken or weakened assumption: Proof ownership is intentionally not an authorization boundary; anyone may clean another address's permanently unusable proof.
Candidate compositions: Front-running finalization; deleting a proof after a game transition; delete during pause; delete after finalization.
Evidence: v9 `src/L1/OptimismPortal2.sol:707-728`; `src/dispute/AnchorStateRegistry.sol:177-186`; terminal resolution at `FaultDisputeGame.sol:698-717`, `SuperFaultDisputeGame.sol:667-686`, `zk/ZKDisputeGame.sol:570-640`; `ProofLifecycle.t.sol` tests `test_challengerWinsDeletionIsPermissionlessAndLeavesArrayStale`, `test_blacklistedProofCanBeDeletedByAnotherUserWhilePaused`, and `test_deleteFrontRunCannotChangeAnInvalidProofIntoAValidOne`.
Confidence: High.
Reason it may be benign: Both enabling facts are permanent under every configured game family. Immediately before deletion, `checkWithdrawal` already rejects the proof; deletion changes only its revert reason to `Unproven`.
