PRIM-ID: PRIM-1002 — `SafeCall.callWithMinGas` floor is now state-dependent (+183,600 for value to a zero-codehash target) and still multiplies a user-supplied uint256 `gasLimit` unchecked

OLD ASSUMPTION: the gas a finalizer must supply is a pure function of the withdrawal (`gasLimit * 64/63 + 40,000`),
and "`gasLimit` is the minimum the target receives".

NEW U21 CONDITION: v9 `SafeCall.callWithMinGas` reads `_target.codehash` and adds `NEW_ACCOUNT_STATE_GAS = 183_600`
to the reserve when `_value != 0 && codehash == 0` (`SafeCall.sol:9,131-132`). This is live in the portal
today (portal impl `0xb20b23af…` == v9 build), although L1 does not run EIP-8037: the real extra cost is 25,000.
The only v8->v9 library change with runtime effect (RLPReader, LibPosition, LibUDT, LibGameArgs, PreimageOracle,
MIPS64*, GasPayingToken, ProxyAdmin, ProxyAdminOwnedBase, LivenessModule, FeeVault, LegacyMintableERC20 are
whitespace-identical; Burn and MIPS64Memory differ only in comments).

COMPOSITION POSSIBILITY: (a) relayers / contracts that pre-compute finalize gas from the withdrawal alone now
under-supply for value withdrawals to never-used L1 addresses (revert, retry). (b) the floor can be changed by
a third party between gas estimation and inclusion: sending 1 wei to the target makes `codehash != 0` and
lowers the floor (never raises it), so no griefing direction exists. (c) `mul(_minGas, 64)` in `hasMinGas`
(`SafeCall.sol:107`) wraps for `gasLimit >= 2^250`; `L2ToL1MessagePasser.initiateWithdrawal` takes a uint256.

REQUIRED ATTACKER CONTROL: for (c) the attacker must be the withdrawal's own initiator.

POSSIBLE IMPACT: none against third parties found. (c) is self-inflicted: the initiator declares a huge gasLimit
and receives no guarantee.

Source contracts: `src/libraries/SafeCall.sol`, `src/L1/OptimismPortal2.sol`.
Exact functions: `SafeCall.hasMinGas`, `SafeCall.callWithMinGas`, `OptimismPortal2.finalizeWithdrawalTransactionExternalProof` (:627).
Trigger: finalize a non-messenger withdrawal.
Attacker-controlled inputs: finalize tx gas; (c) withdrawal `gasLimit` (own withdrawal only).
Required state: proven mature withdrawal.
State mutation: `finalizedWithdrawals[hash] = true` regardless of call success for non-L2CDM senders.
External calls: lockbox.unlockETH, target call, lockbox.lockETH on failure.
Cross-contract dependency: live account state of the target (EXTCODEHASH), L1 gas schedule.
Broken or weakened assumption: purity of the gas floor; "gasLimit is a floor" for values >= 2^250.
Candidate compositions: an L2 contract that forwards a user-supplied uint256 gas limit into
`L2ToL1MessagePasser.initiateWithdrawal` for funds it custodies for somebody else (none among predeploys:
L2CDM uses uint64 `baseGas`, FeeVault a constant, `receive()` 100,000).
Evidence: `test/poc/lane10/SafeCallFloor.t.sol` on the deployed portal at block 26433900
(`evidence/lane10/safecall-floor.log`): minimum finalize gas for 1 wei to a non-existent account 361,500 vs
175,000 to an existing account (delta 186,500 = 183,600 * 64/63) vs 158,500 for zero value;
`test_uint256_gasLimit_wraps_floor`: a withdrawal declaring `gasLimit = 2^250` finalizes with a 200,000-gas
call and its target observes 79,580 gas.
Confidence: high.
Reason it may be benign: the extra reserve only makes finalization need more gas (always available to the
finalizer); the overflow needs the victim to be the initiator. Messenger withdrawals are unaffected
(target is the L1CDM, `baseGas` is uint64).
