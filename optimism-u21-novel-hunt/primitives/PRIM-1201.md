PRIM-ID: PRIM-1201 — L1 relay reserve raised by 105,000 gas with no L2 counterpart: measured remaining margin, and public getters that report the wrong side

Source contracts: src/universal/CrossDomainMessenger.sol, src/L1/L1CrossDomainMessenger.sol, src/libraries/GasConstants.sol,
  src/libraries/SafeCall.sol, src/L1/OptimismPortal2.sol (v9 @ ba6fcadb); live L2CrossDomainMessenger v2.2.1 on OP Mainnet.

Exact functions: CrossDomainMessenger.relayMessage (L209-307: `hasMinGas(_minGasLimit, _localRelayReservedGas() + _localRelayGasCheckBuffer())`
  L266, `SafeCall.call(_target, gasleft() - _localRelayReservedGas(), …)` L285); L1CrossDomainMessenger constants L43-74
  (LOCAL 135,000 / 15,000 internal; public `RELAY_RESERVED_GAS` / `RELAY_GAS_CHECK_BUFFER` alias the REMOTE 40,000 / 5,000);
  L1CrossDomainMessenger.baseGas L117-126; OptimismPortal2.finalizeWithdrawalTransactionExternalProof L627 / L651.

Trigger: any finalize of a messenger withdrawal. The withdrawal's `gasLimit` was computed on L2 by a messenger that
  was NOT upgraded (U21 has no L2 fork) and still budgets 200,000 + 40,000 + 40,000 + 5,000; the L1 messenger now needs
  `minGas*64/63 + 190,000` at its gas check (v8: `+ 85,000`).

Attacker-controlled inputs: gas supplied to `finalizeWithdrawalTransactionExternalProof` (anyone may finalize anyone's
  matured withdrawal); message size and `minGasLimit` if the attacker is the L2 sender.

Required state: none beyond a proven, matured messenger withdrawal.

State mutation: none by itself. It narrows the slack that guarantees "a relay given exactly the withdrawal gasLimit
  executes the target".

External calls: portal -> L1CDM -> SystemConfig -> portal -> lockbox -> SuperchainConfig (pause), -> target.

Cross-contract dependency: L2 `baseGas` (old constants) vs L1 `relayMessage` (new constants); portal `callWithMinGas`
  guarantees the messenger frame at least the withdrawal gasLimit.

Broken or weakened assumption: "each value must cover the worst case on the chain it is named for" (GasConstants.sol
  header) presumes both messengers carry the split constants. On mainnet only L1 does. Also: an integrator that reads
  `L1CDM.RELAY_RESERVED_GAS()` to size an L1 relay gets 40,000, not the 135,000 the contract uses.

Candidate compositions:
  - Amsterdam (EIP-8037) activating on L1 before the L2 messenger is upgraded: the source's own figure is 391,338 gas
    for an empty value-to-new-account message against an L2 budget of 310,160 (GasConstants.sol L39-43). Outcome would
    be a portal revert (`OptimismPortal_L1CDMCallFailed`, retry with more gas) or a replayable failed message — not a
    loss, because of the revert added in the same release.
  - Any further growth of the pre-check path (the pause read is already four proxy hops) eats the remaining ~59k.
  - Third-party relayers / SDKs that submit finalize with exactly the estimated gas.

Evidence:
  - cast: L2CDM (l2 fork) version 2.2.1, `baseGas("",0)` = 310160, RELAY_RESERVED_GAS 40000, RELAY_GAS_CHECK_BUFFER 5000;
    L1CDM version 2.13.0, `baseGas("",0)` = 310160, public RELAY_RESERVED_GAS 40000, RELAY_GAS_CHECK_BUFFER 5000
    (evidence/lane12/lane12-cast-evidence.txt §2).
  - test/poc/lane12/Lane12.t.sol, messenger frame called as the portal from a cold context:
      empty msg, minGas 100,000, 1 ETH : budget 411,747, needed 352,835, margin 58,912   (test_R17_frame_empty_minGas100k_value)
      empty msg, minGas 0              : budget 310,160, needed 273,137, margin 37,023   (test_R17_frame_empty_minGas0; the
                                          test receiver itself burns ~75k, so this is not the pure check margin)
      20 kB msg, minGas 200,000        : budget 833,334, needed 525,738, margin 307,596  (test_R17_frame_20kb_minGas200k)
      100 kB msg, minGas 200,000       : budget 4,031,400, needed 872,619                (test_R17_frame_100kb_minGas200k)
    => pre-check overhead ~61k of the 120k left after the reserve; under v8 constants the same margin was ~164k.
  - through the real portal: lowest non-reverting gas already delivers; 500-gas scan (-200k … +150k around the
    threshold) finds 0 "finalized but not delivered" samples (test_R17_gasWindow_*); a gas-burning target is recorded
    as failed, not reverted (test_R18_*).
  - mainnet block 26433900 header has no Amsterdam fields (cast block): the 135,000 reserve is not yet needed on L1.

Confidence: high for the measurements; they are from a forge fork (cold account accesses, EVM version of the
  harness), not from a mainnet transaction.

Reason it may be benign: it is benign today — the delivery guarantee holds with ~59k to spare, and every failure
  mode ends in a retry or a permissionless replay. Recorded because the margin is now thin and one-sided.
  Overlaps lane 04 PRIM-0404 and lane 32 PRIM-3202; the numbers and the getter observation are this lane's.
