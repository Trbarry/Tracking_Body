Broken or weakened assumption: none broken. Precise guarantee: for a game that survives the fault path, extraData is
  byte-for-byte the program's canonical encoding of the super root reached from THAT game's starting anchor, so its
  chain-id multiset equals the anchor root's multiset, sorted ascending. The claim is never decoded by the program, so

  recomputed post-state and is an ordinary invalid claim. A DEFENDER_WINS game with [(10,fake),(10,real)] therefore needs
  (a) zero challengers for 3.5 d (generic 1-of-N failure; see control test) or (b) an anchor root that already has
  that shape (governance-supplied startingAnchorRoot only: OPCM upgrade/migrate input, "nothing on-chain can tell a
  correct anchor from a wrong one").

  exactly [(10,·),(130,·)] ascending — a signer-review item, not permissionless. (ii) type 5 (SuperPermissioned) has NO
  program behind it: on a chain respecting type 5 (Soneium) the proposer alone decides list shape; first-match then
  matters for Guardian review tooling (a duplicate later entry is ignored by the portal).
