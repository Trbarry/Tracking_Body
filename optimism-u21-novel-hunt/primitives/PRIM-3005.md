PRIM-ID: PRIM-3005 — Migrator and validator share one incomplete finite game-type list
Source contracts: `dispute/lib/Types.sol`, `OPContractsManagerMigrator.sol`, `OPContractsManagerMigrationValidator.sol`
Exact functions: `GameTypes.clearedGameTypes`; Migrator `_migratePortal`; Validator `assertLegacyGamesCleared`
Trigger: Planned interop migration of a chain whose old DGF has an implementation under a defined but omitted game type.
Attacker-controlled inputs: Before migration, permissionless game creation if the omitted type is registered; migration inputs are governance-controlled.
Required state: An omitted type (2,3,6,7,254,255,1337) is nonzero in the legacy DGF.
State mutation: Migrator clears only 0,1,8,4,5,9,10, then Portal leaves the old DGF; Validator iterates the identical list.
External calls: Migrator owner-calls old DGF `setImplementation` and upgrades Portal/ASR.
Cross-contract dependency: Enum maintenance, old DGF registrations, planned shared-DGF migration.
Broken or weakened assumption: “All legacy game types cleared” is validated by the same enumeration that performs clearing.
Candidate compositions: Register/create omitted super type 7 before documented migration, retain stale game creation/custody assumptions afterward, and evade post-state validation.
Evidence: `Types.sol:51,75-110`; `OPContractsManagerMigrator.sol:536-555`; `…MigrationValidator.sol:719-750`. At N all omitted OP implementations are zero.
Confidence: High structural gap, low present exploitability.
Reason it may be benign: OP production has only types 5 and 9 nonzero and both are included; interop is not active; direct eligible impact from a leftover factory is unproven.

OLD ASSUMPTION: The hard-coded list exhausts every registration that migration must disable.
NEW U21 CONDITION: List centralization makes Migrator and Validator agree even when both omit a defined type.
COMPOSITION POSSIBILITY: Planned OP/Unichain migration plus a nonzero omitted registration.
REQUIRED ATTACKER CONTROL: Permissionless creation under an already-registered omitted type; registering one requires DGF owner.
POSSIBLE IMPACT: Stale games/bonds, invalid migration assurance, and possible game/withdrawal liveness confusion.
