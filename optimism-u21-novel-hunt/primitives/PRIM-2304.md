PRIM-2304: Portal surplus is a non-liability side pocket swept only by admin migration

Source contracts: OptimismPortal2, ETHLockbox

Exact functions: `donateETH`, `migrateLiquidity`, failed-call relock branch

Trigger: Donation, forced ETH, unlock during finalization, or privileged liquidity migration.

Attacker-controlled inputs: Donation/forced amount; proven withdrawal target behavior.

Required state: None for donation/forced ETH; ProxyAdmin owner for migration.

State mutation: Donations/forced ETH increase portal balance without L2 mint. `migrateLiquidity` reads all `address(this).balance` and locks it. Failed target relocks only `_tx.value`, leaving pre-existing surplus in place.

External calls: Admin sweep calls current lockbox `lockETH` with entire portal balance.

Cross-contract dependency: Only the portal's privileged migration path intentionally reads its full balance.

Broken or weakened assumption: Portal balance is not always zero and is not always a user liability.

Candidate compositions: Reentrancy during transient unlock; forced ETH before migration; CGT prevents sweep.

Evidence: v9 `src/L1/OptimismPortal2.sol:380-383,500-512,659-665`; fork `test_donationAndForcedETHStayInPortalUntilAdminMigration`; modeled direct-failure test preserves a 2 ETH surplus.

Confidence: High.

Reason it may be benign: No permissionless function spends the full balance; donations are surplus and migration is owner-only.
