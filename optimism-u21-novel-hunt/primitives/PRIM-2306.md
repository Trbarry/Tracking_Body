PRIM-2306: Messenger failure has two distinct custody states

Source contracts: OptimismPortal2, L1CrossDomainMessenger, CrossDomainMessenger

Exact functions: `finalizeWithdrawalTransactionExternalProof`, `relayMessage`

Trigger: Finalization of an L2CrossDomainMessenger withdrawal.

Attacker-controlled inputs: Authenticated cross-domain target/message/value/min gas and transaction gas supplied by the finalizer.

Required state: Mature valid messenger withdrawal.

State mutation: If `relayMessage` returns normally after its inner target fails, messenger records `failedMessages` and retains value for replay. If portal-to-messenger CALL itself returns false, v9 throws `OptimismPortal_L1CDMCallFailed`, rolling back unlock and finalization.

External calls: Portal -> L1 messenger -> arbitrary message target.

Cross-contract dependency: Portal classifies the path using withdrawal sender equal to the L2 messenger predeploy; messenger authenticates portal and portal `l2Sender`.

Broken or weakened assumption: A boolean success from the outer SafeCall does not equal success of the inner cross-domain message.

Candidate compositions: Gas boundary changes; replay escrow; unsafe messenger target; legacy already-relayed message.

Evidence: v9 `src/L1/OptimismPortal2.sol:639-653`; `src/L1/L1CrossDomainMessenger.sol:136-143`; `src/universal/CrossDomainMessenger.sol:239-306`; real relay trace and etched outer-failure rollback test.

Confidence: High.

Reason it may be benign: Both branches preserve backing exactly once: either the messenger holds replay value or the entire unlock reverts.
