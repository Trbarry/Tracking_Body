PRIM-ID: PRIM-0501 — exact semantics of the permissionless proof deletion
Source contracts: OptimismPortal2 v6.1.0 (impl 0xb20b23af6071405c37ddda0c0640e8ebb7899645, shared by the OP/Ink/Soneium/Unichain portal proxies); AnchorStateRegistry v4.0.0 (impl 0x2b27299c…, shared by all four ASR proxies)
Exact functions: `OptimismPortal2.deleteProvenWithdrawal(bytes32,address)` (src/L1/OptimismPortal2.sol:711-728); `AnchorStateRegistry.isGameBlacklisted` (:252); game `status()`
Trigger: any caller, any time (no pause check, no finalized check, no reentrancy guard, no caller/submitter relation)
Attacker-controlled inputs: `_withdrawalHash`, `_proofSubmitter` (any existing slot)
Required state: `provenWithdrawals[h][s].timestamp != 0` AND ( `storedGame.status() == CHALLENGER_WINS` OR `portal.anchorStateRegistry().disputeGameBlacklist[storedGame]` )
State mutation: exactly one slot zeroed: `provenWithdrawals[h][s]` (slot keccak(s . keccak(h . 57))). `proofSubmitters[h]` (slot 60) is NOT touched; `finalizedWithdrawals[h]` is NOT touched. Emits `WithdrawalProofDeleted(h, s)`.
External calls: `storedGame.status()` (STATICCALL to the stored clone), `anchorStateRegistry.isGameBlacklisted(storedGame)` — against the portal's CURRENT registry, not the registry the game was created under.
Cross-contract dependency: status is write-once in every deployed game impl (`resolve()` requires IN_PROGRESS: SuperFaultDisputeGame.sol:675, ZKDisputeGame.sol:577, FDG idem); the deployed ASR has only five mutators (`setAnchorState`, `initialize`, `blacklistDisputeGame`, `setRespectedGameType`, `updateRetirementTimestamp` — `cast selectors` of the impl), i.e. no un-blacklist and no way to lower `retirementTimestamp`.
Broken or weakened assumption: none for the notice's claim. Measured boundary matrix (fork, real code, `DeletePredicateTest.test_predicate_matrix`):

| stored game state | delete | proof can still finalize? |
|---|---|---|
| no entry | revert `OptimismPortal_Unproven` | – |
| IN_PROGRESS | revert `OptimismPortal_DisputeGameNotInvalidated` | maybe |
| DEFENDER_WINS (also when called by the submitter himself) | revert NotInvalidated | yes |
| DEFENDER_WINS + retired (`updateRetirementTimestamp`) | revert NotInvalidated | never (dead, not cleanable) |
| respected type changed after creation | revert NotInvalidated | yes |
| paused only | revert NotInvalidated | after unpause |
| CHALLENGER_WINS (also while the chain is paused) | succeeds for anyone | never |
| blacklisted (any status, incl. IN_PROGRESS) | succeeds for anyone | never |
| blacklisted AFTER the withdrawal was finalized | succeeds; `finalizedWithdrawals` stays true | n/a |

Deletable ⊂ permanently-unfinalizable (under a fixed registry): `checkWithdrawal` needs `isGameClaimValid` ⇒ `!blacklisted ∧ status == DEFENDER_WINS` (AnchorStateRegistry.sol:293,348).
Candidate compositions: (a) with PRIM-0503 — attacker makes an honest user's proof land on a doomed game, then anyone erases it; (b) indexers: `WithdrawalProofDeleted` can fire for an already-finalized withdrawal and for a `(h, s)` that still appears in `proofSubmitters[h]`; (c) after a registry swap the blacklist consulted is the new ASR's (PRIM-0504).
Evidence: test/poc/lane05/Lifecycle.t.sol, CrossVersion.t.sol (`test_v8_proof_finalizes_under_v9`), evidence/lane05-forge-test-output.txt; survey of 44 real proofs (41 created under v8 in blocks 26425493–26429992, 3 under v9): 0 deletable.
Confidence: high
Reason it may be benign: it is benign on-chain — the predicate is a strict subset of "can never finalize", the write is confined to one mapping slot keyed by (hash, submitter), and re-proving was always possible by overwrite.
