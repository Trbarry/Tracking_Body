PRIM-ID: PRIM-0803 — Third party can finalize a victim's messenger withdrawal undelivered (replayable) via the
  `xDomainMsgSender` re-entrancy branch
Source contracts: L1CrossDomainMessenger 2.13.0 (same code in 2.11.1), OptimismPortal2.
Exact functions: `relayMessage` replay path (CrossDomainMessenger.sol:245-247, 265-281) ->
  attacker target -> `OptimismPortal2.finalizeWithdrawalTransactionExternalProof(victimTx, victimSubmitter)`.
Trigger: attacker replays one of his own failed messages; its target finalizes the victim's withdrawal while
  `xDomainMsgSender != DEFAULT_L2_SENDER`.
Attacker-controlled inputs: his own message/target; timing; which matured victim withdrawal.
Required state: attacker owns one failed message (send any L2 message to a target that reverts once — cost: one
  normal withdrawal); victim withdrawal proven and matured but not yet finalized.
State mutation: victim `finalizedWithdrawals = true`, victim `failedMessages = true`, victim `_value` parked in L1CDM.
External calls: L1CDM -> attacker target -> portal -> L1CDM (records failed, returns).
Cross-contract dependency: portal's `l2Sender` guard does not cover a messenger replay started outside the portal.
Broken or weakened assumption: "finalization of a messenger withdrawal executes the message" — it may only record it.
Candidate compositions: needs a victim whose L1 handler is not replay-tolerant (must run in the finalize tx, or has
  a deadline); none in the canonical bridges. Unchanged by U21.
Evidence: test_S2_reentrantFinalize_marksVictimFailed_noDoubleDelivery (passes on l1 and l1pre): victim target hit
  count 0 after the attack, 1 after the public replay, second replay and second finalize revert.
Confidence: high.
Reason it may be benign: exactly-once delivery is preserved; cost to the victim is one replay transaction.
