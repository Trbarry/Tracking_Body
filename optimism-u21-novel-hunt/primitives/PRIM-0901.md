PRIM-ID: PRIM-0901 — retired per-chain ETHLockbox stays an authorized, non-blacklisted withdrawal target after `migrate`
Source contracts: src/L1/ETHLockbox.sol, src/L1/OptimismPortal2.sol, src/L1/opcm/OPContractsManagerMigrator.sol (v9 @ ba6fcadb)
Exact functions: OptimismPortal2._isUnsafeTarget (L846-849), finalizeWithdrawalTransactionExternalProof (L577-666),
  ETHLockbox.lockETH (L144-151), unlockETH (L157-178), OPContractsManagerMigrator._migratePortal (L475-556)
Trigger: after the PLANNED OP Mainnet(10)+Unichain(130) `OPContractsManagerV2.migrate`, any L2 user initiates a
  withdrawal on chain A with `target = <chain A's retired lockbox>` and finalizes it on L1.
Attacker-controlled inputs: withdrawal target, value, calldata (L2-originated, arbitrary).
Required state: post-migration. `portal.ethLockbox == shared`, so `_isUnsafeTarget` only blocks {portal, shared lockbox};
  `oldLockbox.authorizedPortals[portal]` is never cleared (no de-authorize function exists; mapping only ever set to true, L231).
State mutation:
  - `lockETH()` with value v: portal unlocks v from the SHARED lockbox, then the retired lockbox accepts it as an
    authorized-portal lock -> v sits in the retired lockbox (shared -v, retired +v). Withdrawal is "successful".
  - `unlockETH(x)`: reverts `ETHLockbox_NoWithdrawalTransactions` (L169-171) because `portal.l2Sender() != DEFAULT`.
    This is now the ONLY guard (the BadTarget guard no longer covers the retired lockbox).
External calls: portal -> sharedLockbox.unlockETH -> portal.donateETH; portal -> retiredLockbox.lockETH.
Cross-contract dependency: Migrator authorizes portal on the new lockbox and repoints the portal, but leaves the old
  portal<->old lockbox authorization and never adds the old lockbox to any unsafe-target list.
Broken or weakened assumption: "every lockbox on which a portal is authorized is an unsafe withdrawal target for that portal"
  (true today for all four chains, false for retired lockboxes after migration). Defense-in-depth drops from 2 guards to 1.
Candidate compositions:
  - Any future code path that lets a portal call out with `l2Sender == DEFAULT` to an attacker-chosen address
    (none exists in v9: grep of all `.call`/SafeCall sites in OptimismPortal2 = only L627 inside the l2Sender window).
  - ETH parked in a retired lockbox is outside the shared pool and invisible to `ethLockbox`-based monitoring; only the
    ProxyAdmin owner can sweep it (`oldLockbox.migrateLiquidity(shared)`, L203-216; repeatable because
    `shared.authorizedLockboxes[old]` is permanent).
Evidence: test/poc/lane09/Lane09PostMigration.t.sol::test_post_target_oldLockbox_lockSucceeds_unlockBlocked (real deployed
  OPCM 0x2d91e6F2… migrating real OP+Unichain state on fork `l1`; proof validity mocked only to inject the withdrawal);
  post-migration reads: oldOP.authorizedPortals[opPortal]=true, oldUNI.authorizedPortals[uniPortal]=true, balances 0.
Confidence: high (behaviour), impact none by itself.
Reason it may be benign: only the withdrawer's own, legitimately withdrawn ETH can be parked; nothing can be pulled out
  by a non-owner; retired lockbox balance is 0 right after migration. Self-harm / cosmetic.
