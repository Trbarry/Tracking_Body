PRIM-ID: PRIM-0305 — The chain's pause key is the lockbox address; deposits keep locking while paused

Source contracts: `src/L1/ETHLockbox.sol`, `src/L1/OptimismPortal2.sol`, `src/L1/SystemConfig.sol`, `src/L1/SuperchainConfig.sol`.

Exact functions: `ETHLockbox.paused` (`:112-114`), `OptimismPortal2.paused` (`:306-308`), `SystemConfig.paused` (`:574-576`), `SuperchainConfig.isLocalOrGlobalPaused` (new in v2.5.0), `ETHLockbox.lockETH` (`:144-151`, no pause check), `unlockETH` (`:159`).

Trigger: guardian calls `SuperchainConfig.pause(identifier)`.

Attacker-controlled inputs: none (guardian action); users choose whether to deposit during a pause.

Required state: none.

State mutation:

| Guardian call | `portal.paused()` / `SystemConfig` / `L1CDM` / `ASR` |
|---|---|
| `pause(address(portal))` | false (withdrawals still finalize) |
| `pause(address(lockbox))` | true |
| `pause(address(0))` | true (global) |

While paused: `depositTransaction{value}` still locks ETH; `finalize…` reverts `OptimismPortal_CallPaused`; `unlockETH` reverts `ETHLockbox_Paused`.

External calls: `superchainConfig.isLocalOrGlobalPaused(lockbox)`.

Cross-contract dependency: v9 routes every pause getter through `ethLockbox.paused()`; in v8 `SystemConfig.paused()` chose between lockbox and portal by feature flag. For OP, Ink, Soneium and Unichain the key was already the lockbox before U21, so it did not change.

Broken or weakened assumption: none in the contracts. Tooling that pauses by portal address would have no effect.

Candidate compositions: for the pause lane — any contract still resolving pause through a different lockbox than the portal's. At block 26433900 `portal.ethLockbox == ASR.ethLockbox == DelayedWETH.ethLockbox` on all four chains.

Evidence: `test_E_pause_identifierIsLockbox_depositsStillLock_withdrawalsBlocked` (`vm.prank(guardian)`, a state production can be in).

Confidence: high.

Reason it may be benign: by design ("unlocks are blocked when paused, locks are not", `ETHLockbox.sol:158`); no value is duplicated or stranded, withdrawals resume after unpause.
