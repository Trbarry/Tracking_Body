PRIM-ID: PRIM-0306 — Withdrawal targets v9 does not forbid: previous lockboxes and sibling portals after an interop migration

Source contracts: `src/L1/OptimismPortal2.sol`, `src/L1/ETHLockbox.sol`, `src/L1/opcm/OPContractsManagerMigrator.sol`.

Exact functions: `_isUnsafeTarget` (`OptimismPortal2.sol:846-849`: only `address(this)` and the current `ethLockbox`), `ETHLockbox.lockETH` (`:144-151`), `unlockETH` (`:157-178`), `_migratePortal` (`OPContractsManagerMigrator.sol:475-556`).

Trigger: after the planned interop migration, a withdrawal on chain A targets (a) A's old per-chain lockbox, or (b) chain B's portal, which shares the new lockbox.

Attacker-controlled inputs: target, calldata, value of their own withdrawal.

Required state: `migrate()` executed by the PAO (not the case today: INTEROP is false on all four chains). Old lockbox keeps `authorizedPortals[portalA] == true`; authorizations cannot be revoked.

State mutation (from code, not executed on a fork):

| Target and call | Result |
|---|---|
| old lockbox `unlockETH(x)` | reverts `ETHLockbox_NoWithdrawalTransactions` (`ETHLockbox.sol:169-171`); old balance is 0 anyway |
| old lockbox `lockETH{value}` | accepted: the withdrawal's own value is moved shared lockbox → old lockbox and stays there until the PAO calls `migrateLiquidity` |
| portal B `depositTransaction{value}` | accepted: value returns to the shared lockbox, liability moves from chain A to chain B |
| portal B `donateETH{value}` | accepted: stranded in portal B |
| portal B `finalize…` | accepted: portal B has its own `l2Sender`; an ordinary finalization |

External calls: as listed.

Cross-contract dependency: for old lockboxes the `l2Sender` check inside `unlockETH` is the only barrier, because `_isUnsafeTarget` tracks only the current lockbox.

Broken or weakened assumption: none found. Each case moves only the withdrawer's own value.

Candidate compositions: a lane that executes the Migrator on a fork should assert these four rows against real code, and check that no old lockbox retains a balance after migration.

Evidence: code reading only for the post-migration rows. The `l2Sender` guard itself was hit with a mocked caller in `test_B_unlockGuard_l2Sender_mockedPortalCaller` (`vm.prank(portal)` + `vm.store`), which only locates the guard.

Confidence: medium (not executed end to end).

Reason it may be benign: self-harm only; no path unlocks more than the withdrawal's value.
