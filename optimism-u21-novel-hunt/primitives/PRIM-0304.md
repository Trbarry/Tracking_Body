PRIM-ID: PRIM-0304 — Finalizing a victim's messenger withdrawal from inside an L1CDM replay moves its ETH from the lockbox into L1CDM

Source contracts: `src/universal/CrossDomainMessenger.sol`, `src/L1/L1CrossDomainMessenger.sol`, `src/L1/OptimismPortal2.sol`.

Exact functions: `relayMessage` (`CrossDomainMessenger.sol:209-307`, re-entry branch `:265-282`), `_isOtherMessenger` (`L1CrossDomainMessenger.sol:136-138`), `finalizeWithdrawalTransactionExternalProof` (`OptimismPortal2.sol:594-596`).

Trigger:
1. Attacker owns one L2→L1 message whose L1 target they control and makes it fail once (it lands in `failedMessages`).
2. Attacker replays it. Inside the target callback, `portal.l2Sender == DEFAULT` (a replay is not a portal finalization) while `L1CDM.xDomainMsgSender` is set.
3. The callback calls `portal.finalizeWithdrawalTransactionExternalProof(victimTx, submitter)` for any ready withdrawal sent by `L2CrossDomainMessenger`.
4. The portal unlocks the value and calls `L1CDM.relayMessage{value}`; L1CDM sees `xDomainMsgSender != DEFAULT`, sets `failedMessages[victimHash] = true` and returns.

Attacker-controlled inputs: which victim withdrawal; when.

Required state: one attacker message in `failedMessages`; victim withdrawal proven, mature, not finalized.

State mutation (measured on the fork, victim = real 638.177 ETH withdrawal `0xb16e5fc2…d612`):

| | before | after step 4 | after a later replay |
|---|---|---|---|
| lockbox | L | L − 638.177 ETH | L − 638.177 ETH |
| L1CDM | c | c + 638.177 ETH | c |
| `portal.finalizedWithdrawals[victim]` | false | true | true |
| `L1CDM.failedMessages[victimHash]` | false | true | true |
| `L1CDM.successfulMessages[victimHash]` | false | false | true |
| victim's L1 target | unpaid | unpaid | called once with the value |

External calls: portal → lockbox, portal → L1CDM.

Cross-contract dependency: the portal's guard is `l2Sender`, the messenger's guard is `xDomainMsgSender`; they are independent, so the portal accepts the nested call and the messenger refuses to execute it.

Broken or weakened assumption: "a withdrawal's value leaves the lockbox only when it is delivered". It can instead be parked in L1CDM, which holds 0 ETH on all four chains today.

Candidate compositions: any future logic that treats L1CDM's balance as empty or sweeps it; a victim target that only works when called in the finalization tx (`portal.l2Sender() == L2CDM`) or before a deadline.

Evidence: `test_H_nestedFinalizeInsideReplay_parksVictimValueInCDM_thenReplayPaysOnce` (attacker recipient code substituted with `vm.etch`; victim withdrawal and all protocol contracts are real). The same test shows the replay pays exactly once and a second replay reverts.

Confidence: high for the mechanics.

Reason it may be benign: the code comment at `CrossDomainMessenger.sol:263-264` describes this branch as intended; the victim's message stays replayable by anyone; unchanged from v8. Impact is one extra L1 transaction for the victim.
