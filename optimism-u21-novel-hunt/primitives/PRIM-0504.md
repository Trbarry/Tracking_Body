PRIM-ID: PRIM-0504 — dead-but-undeletable proofs; deletion's blacklist check is relative to the portal's current registry
Source contracts: OptimismPortal2 v6.1.0, AnchorStateRegistry v4.0.0, OPContractsManagerMigrator (v9)
Exact functions: `deleteProvenWithdrawal` (:711), `checkWithdrawal` (:671), `migrateToSharedDisputeGame` (:528), `AnchorStateRegistry.isGameRegistered/isGameRetired/initialize` (:227, :259, :130), `OPContractsManagerMigrator.migrate/_migratePortal`
Trigger: (a) guardian `updateRetirementTimestamp()`; (b) the future ProxyAdminOwner-only migration, which deploys a fresh DGF + ASR and repoints the portal
Attacker-controlled inputs: none
Required state: a stored proof whose game is not CHALLENGER_WINS
State mutation: none by an attacker. Observation: such proofs can never finalize (`isGameClaimValid` false forever) yet `deleteProvenWithdrawal` reverts `DisputeGameNotInvalidated`, so the notice's cleanup covers only two of the permanent-invalidation causes. After a swap: old-registry blacklist entries are ignored, new-registry blacklist entries (the guardian may blacklist any address) make old proofs deletable.
External calls: n/a
Cross-contract dependency: invalidation after the swap is double-locked — (1) `newASR.isGameRegistered(old)` is false because the clone address depends on the factory (CREATE2 from the DGF), even if a game with identical (type, rootClaim, extraData) is re-created in the new factory; (2) a fresh ASR sets `retirementTimestamp = block.timestamp`, retiring every pre-existing game.
Broken or weakened assumption: none security-relevant; the "proof whose game can never lead to finalization" set is strictly larger than the deletable set.
Candidate compositions: none found. A proof cannot survive the swap; an attacker-prepositioned shadow proof against an old-factory game stays dead even if a twin game in the new factory wins.
Evidence: `MigrationSurvivalTest.test_proofs_do_not_survive_registry_swap` (fresh proxies running the real deployed ASR/DGF implementations, real portal, real type-9 implementation re-registered with args pointing at the new ASR; all privileged pranks model the documented migration): old real proof → `InvalidRootClaim`; delete → NotInvalidated; twins land at 0x40D4…/0x6847… ≠ old proxies; old-ASR blacklist ignored; new-ASR blacklist enables delete. `DeletePredicateTest` branch A2 for retirement.
Confidence: high (simulation uses the same-lockbox variant of the swap, not the full `OPContractsManagerV2.migrate` transaction)
Reason it may be benign: purely a cleanup-coverage gap; users overwrite by re-proving.
