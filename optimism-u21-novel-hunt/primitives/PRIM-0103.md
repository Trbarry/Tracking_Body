PRIM-ID: PRIM-0103
Title: DelayedWETH answers every unknown selector with success and empty returndata (payable fallback = deposit)

Source contracts: `src/universal/WETH98.sol:56-63` (`receive`/`fallback` -> `deposit()`), `src/dispute/DelayedWETH.sol` (v2.0.0, proxies `0x1B6DBF05...` OP, `0x57b4C29D...` Ink, `0x18fBb58C...` Soneium, `0x74ad145a...` Unichain; also the legacy proxies).

Exact functions: `fallback()`; relevant removed/added getters: `systemConfig()` (removed in v2.0.0), `ethLockbox()` (absent before v2.0.0).

Trigger: any call with a selector the implementation does not have.

Attacker-controlled inputs: none beyond the selector/value.

Required state: none.

State mutation: `_balanceOf[msg.sender] += msg.value` (zero for a plain call).

External calls: none.

Cross-contract dependency: callers that probe a DelayedWETH with a low-level call and only test `success`; callers that use a typed call get a decode revert instead of a clean "function missing" revert; StorageSetter selectors sent to a DelayedWETH proxy succeed silently.

Broken or weakened assumption: "a removed getter reverts". ETHLockbox and AnchorStateRegistry revert on `systemConfig()` after U21; DelayedWETH does not.

Candidate compositions:
- `OPContractsManagerMigrationValidator.assertLegacyPauseRouting` (lines 639-647) calls `legacyWETH.ethLockbox()` with a typed call: against a pre-v2 DelayedWETH (e.g. OP's `0xD061AB95...` v1.5.0) the whole validation reverts instead of reporting `MIG-CHAIN-n-190`. View-only tooling impact.
- `OPContractsManagerUtils._adminFor` uses `try IProxyAdminOwnedBase(target).proxyAdmin()`; a target with a swallow-all fallback and no `proxyAdmin()` makes the try block's decode revert (not caught). Not reachable with the current DelayedWETH, which has `proxyAdmin()`.

Evidence: `cast call 0x1B6DBF05EaF22d4E70dC993e8a19dd9F3dcb3162 "systemConfig()(address)"` on `l1` -> "ABI decoding failed: buffer overrun" (success, 0 bytes); on `l1pre` the same happens for `ethLockbox()`. Fork test `test_noProxyLeftOnStorageSetter` shows `setBytes32(bytes32,bytes32)` on a DelayedWETH proxy returns success with empty data.

Confidence: high (behaviour), low (usefulness).

Reason it may be benign: WETH9-compatible behaviour, long-standing; OPCM `loadOrDeployProxy` checks `result.length >= 32`; no on-chain mutator trusts a bare `success` from a DelayedWETH.
